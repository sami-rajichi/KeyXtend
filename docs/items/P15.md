## Notes

- G15 (macOS and Ubuntu on GitHub's machines) can run earlier, once the Qt keyboard builds there; it needs the owner's yes to push.
- G16 runs in a Linux virtual PC: GNOME and KDE, Wayland and X11.
- macOS and Linux each add their own shortcuts table (ADR-0031). The agreement test `apps/keyxtend/tests/agree/shortcuts.rs` reads only Windows' table and runs only on Windows, so give each new table the same checks (from P6, 2026-10-23).
- Some shortcut names are Windows product names (File Explorer, Task Manager, Lock PC), so macOS and Linux need their own names for those, per platform (from P6, 2026-10-23).
- `cpal` is a Windows-only worker dependency for now, as Linux CI lacks the ALSA headers (`libasound2-dev`); elsewhere the microphone answers NoMic. Each platform also fills `SessionWatch` from its own lock and sleep signals, and uses Metal or Vulkan for the engine's card part (from P11).
- Snip fills four neutral ports on each system: freeze and list windows (`kx_platform::snip::Desk`), shield, record into MP4 with the system's encoder, and the system's dialogs. Off Windows today `kx-platform-record`'s `NoStudio` answers `NoVideo` and `NoDialogs` shows none; on Wayland the portal asks before any capture (ADR-0056, from P12).
- `FolderPath`, `path_ok` and `SnipFile` take drive paths only today; move them to each system's own paths together (from P12).
- The Quick tests' window check (`native_shown` in `kx-ui/cpp/snipprobes.h`, debug probes only) falls back to Qt's `isExposed()` off Windows, which may fail once Linux builds `kx-ui` with Qt; its `native_above` checks the native stack only on Windows and passes elsewhere (from P12).

## Ideas

- 2026-10-10: the Windows key shows the system's own mark, so the keyboard feels native on each system.
  - Today one theme token picks the drawing (`icons.toml` `win = "win-logo"`); it should come from each platform's adapter table instead.
  - On macOS the key is Command, drawn as ⌘ (Apple's keyboards print ⌘, not the Apple logo, which Apple restricts). On Linux it is Super; check Tux's licence and GNOME/KDE's own drawing before choosing.
- 2026-10-10: every rule of the keyboard core must hold on every system, not only Windows.
  - For example, a key that types nothing with Shift or `AltGr` shows empty (P3). Each system's layout reader must report "types nothing" the same way (macOS `UCKeyTranslate`, Linux xkbcommon).
