A heap decommit after each look change is built (ADR-0023, 2026-10-11). All figures below come from a release build with debug assertions, since the shipping build cannot churn.

Live heap blocks stay flat; the rest is free heap space too scattered to give back.
  - Five warm-up rounds do not pass reliably: +1.6 / +2.4 MB (median of 4) against +4.0 / +7.3 with one on the same build, but one run still grew 4.7 MB of commit. The segment heap with five also had one run of 4 over (ADR-0023, 2026-10-11).
  - G8 now warms up for five rounds (owner's decision), and its result records the warm-up rounds and lists each measured round's memory in `churn.per_round`, so a failed run shows a steady climb (a leak) or one jump (settling) (2026-10-11).
  - G8's churn growth compares the median of the first 5 measured rounds with the median of the last 5 (`[g8] churn_median_rounds`), not two single readings, so one high reading at either end does not decide it; the result shows both medians (owner's decision, 2026-10-11).
  - While a gate runs, `kx-gates` ignores the physical mouse (`[mouse_guard]` in `kx-gates.toml`), so a resting hand cannot show a tip mid-churn; holding a button for 2 s gives the mouse back and stops the gate, and the guard lets go after 6 minutes at most (owner's decision, 2026-10-11).

- **Handled** (`apps/keyxtend` `log.rs`, `run.rs`): The app installs the redacted log subscriber (`log_level`, `log_max_mb`) and calls the kernel's boot and stop.
- **Handled** (`apps/keyxtend` `quiet.rs`): The app installs a quiet panic hook that logs only the location, never the payload, because caught module panics still print through the default hook.
- **Handled** (`apps/keyxtend` `log.rs`): `LogFile::open` returns an error when the previous log cannot be replaced; the app then runs without a file log and says so once.
- **Handled** (`Kernel::load`, then `start`): The kernel cannot yet give `[kernel] log_level` and `log_max_mb` before modules start; split `boot` into load and start, or add a settings getter, so the log opens first.

- **Handled** (`notice.settings-locked`): A settings file that cannot be opened for a reason other than "not found" (for example another program's lock) counts as damaged, so a short lock could set a healthy file aside. Treat such errors as "try again": run on defaults in memory and do not save.
