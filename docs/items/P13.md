## Notes

- The Settings window has its own icon, follows the keyboard's language and carries each theme as strongly as the keyboard does (owner, 2026-09-29).
- The list panel is rebuilt to the full mock-up design.
- Page numbers use Western digits, also in Arabic ("1 من 2").
- Each earlier phase adds its own settings with defaults; this phase gives them their pages.
- A malformed `version` (for example a string) resets the whole section; consider treating it as the current version, so each value is repaired on its own.
- P3 adds a theme button to the top bar as a trial; the owner decides here whether it stays, and the theme choice is in Settings either way.
- P3 builds all three language-key designs (Carousel, Cycle, List); Settings lets the user pick one.
- The Settings window starts from the current effective `[layouts] short` map, because a user map replaces the default (setting `fa` alone drops `ar = "ع"`).
- A module that boot stopped quietly (its provider is switched off and blocked) stays stopped if that provider is later switched on and fails, and only the provider shows a notice; Try again on a module that waits for a provider sends module-failed again (2026-10-01). Show waiting modules in the Settings window (from P3).
- G25 does not drive the List design; List switching is tested only by kx-mod-keyboard's `lang_pick` tests and goldens (from P3).
- A short name's length must not count harakat, as `[layouts] short` refuses عَرَب today, and one bad short name must not reset the whole map (from P3, 2026-10-01).
- With Settings in front, the layout source reads our own thread's layout; hide our Settings window from it, so the keyboard keeps following the app the user types into (from P3, 2026-10-01).
- Add a `[ui]` cap on the window guard's lift-backs, so a program that keeps dropping our window cannot hold it in a loop (`docs/security/kx-platform-windows.md`, from P3, 2026-10-01).
- The guard's focus token is taken once, when `Hub::new` starts (`crates/kx-ui/src/hub.rs`), and every guard run gives it back (`hub/face.rs`), so hours later it may name a stale window. When Settings, our one activating window, arrives, track the last foreground window that is not ours (from P3, 2026-10-01).
- Plate text over a system backdrop (Acrylic, Mica) with a wallpaper of the opposite brightness can fall to about 3.5:1, as the check measures the see-through plate over Windows' plain window colour. The backdrop is off by default; check each material when Settings offers it (`crates/kx-theme/README.md`, from P3, 2026-10-02).
- The user's settings file holds only changed values and no comments (the store writes it with `toml::to_string`), so a person editing it cannot see the bounds. Settings or a file header should show them (owner's wish, 2026-10-02).
- Since texts carry no bidi marks (ADR-0022), the space bar shows the layout name first when the keyboard's text reads the other way from the layout: Hebrew, Persian and Urdu layouts (English text), and a pinned `[ui] language`. Draw its two names as separate pieces in the text's direction; `tst_order`'s 12 expected failures then pass. In Native alone, a leading LRM or RLM would also do, as its fonts have them (ADR-0022) (owner, 2026-10-10).
- Two texts still reach QML without the hub's cleaning: the user's `[layouts] short` names and the layout legends. Clean them as the space bar's names are cleaned (ADR-0022, from P3 review, 2026-10-10).
- Key repeat (spec §4.6, from P3, 2026-10-11): give `[keyboard] repeat` (on or off), `repeat_delay_ms` (the wait before the first repeat) and `repeat_every_ms` (the time between repeats, so lower is faster) a bounded choice each, with the ranges from `settings.rs` and a plain explanation in EN, FR and AR.
- The spike's G7 test panel mirrors with `LayoutMirroring` (`spike/qt-kb/qml/Panel.qml`), and `tst_panel.qml` tests that mirroring, while ADR-0020 and roadmap G7 want Arabic text read right to left in a panel that keeps its places. Drop `LayoutMirroring` when the panel moves, and rewrite those checks (from P3, 2026-10-02).
- The first look change keeps about 19 / 31 MB in Native until the app ends (91.6 / 127.5 at idle, 110.3 / 158.5 after one theme round), so idle after G8's churn stays over 100 / 140; light/dark flips alone keep two thirds of it (from P3, brief D, 2026-10-11).
  - Census: the default heap gains 6–7 MB of small live blocks (about 30 000, mostly 32–128 bytes) and keeps 13–15 MB of free pieces under 4 KB that no decommit returns; the graphics driver keeps about 10 MB more.
  - No effect: releasing hidden windows, QML garbage collection and cache trim, a decommit per heap, releasing at the wake, DXGI's `Trim`.
  - To try: the segment heap (ADR-0023's D2), a heap profile (UMDH or an ETW heap trace, a new tool) to name the small blocks, keeping each look's graphics instead of rebuilding them, and the owner's quiet restart below.
  - ET66 and Dolch idle are over budget too: 102.8 / 142.9 and 104.8 / 149.5.
  - On the installed build with the owner's Dolch at size 0.8, G8 read 121.4 / 171.6 at idle, against 97.8–99.4 / 134.5–137.6 in Native (2026-10-11).
  - The segment heap probe (brief E, five warm-ups) grew a median of +1.8 / +2.0 MB with one run of 4 over 3 MB, held 4–14 MB more working set, and its give-back took 2.6 ms against 0.5 ms (ADR-0023), so it is not promising alone.

## Ideas

- 2026-09-29: Settings cover every behaviour and effect the keyboard offers, each one switchable (for example the click light effect), so each user keeps only what they like.
- 2026-09-29: The theme choice shows a picture of each theme in light and in dark, next to its name.
- **Built in P3 (2026-10-11).** 2026-10-10: Slim the keys so idle memory nears 86 MB (ADR-0021): each key builds only the parts its kind needs, icons are tinted without one effect each, and the lock glow exists only on lit keys (`memory-options.md` measured about 60 MB for the keys today).
- 2026-10-10: In Dolch, Arabic marks sit a little higher above their dotted circle than in Native and ET66 (Noto Sans Arabic's own mark anchors). Check them when the themes are finished (from P3, F2 review m7).
- 2026-10-10: ET66's corner legends have almost no contrast headroom (4.5:1 at a 2.5 px top margin); a small `legend_2` colour nudge would let every theme tuck its corners closer (from P3).
- 2026-10-10: The keyboard's shadow moves in step during a live resize; since P3 it hides until the resize ends, because two windows cannot draw in the same frame. It needs a structural change and an ADR, for example the system's own window shadow.
- 2026-10-10: A "low memory" setting draws without the graphics chip (shared WARP device, about 70 MB), for weak or busy PCs; animations slow down when several windows move.
- 2026-09-29: A setting keeps the quick settings strip always showing under the keyboard; the default stays "only when asked".
- 2026-09-29: An "Open my settings folder" button; the settings file sits in the KeyXtend data folder (P2).
- 2026-09-29: Each theme's picture is a real image file named after the theme, made like the mock-up, so anyone can choose by sight.
- 2026-09-29: Settings, the clipboard history and every panel look attractive and serious, with the best user experience possible.
- 2026-10-01: A minimal keyboard: Settings show or hide each part, so a user keeps only the typing keys if they like. Parts: the side block (right-click, hold and the other mouse keys), the word-actions button, the theme (palette) button, the size buttons (S M L) and the size lens. Default: everything shows, as now.
- 2026-10-02: Settings shows every limited value (such as the keyboard's smallest and largest size) as a bounded choice, never a free text field, so no value out of range can be entered; a value out of range in the file is refused, and the notice says which one and its allowed range.
- 2026-10-11: After a theme or light/dark change, the app restarts itself quietly to drop the memory the change kept, but only while the keyboard is hidden or untouched for a while, never mid-typing, and with any latched modifier or open list kept (owner).
