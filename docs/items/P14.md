## Notes

- Spec §10 asks for no memory growth after 8 hours, while G14 says 4 hours: settle the length here (P3 Task 24 left the row out of G8).
- The keyboard is placed again when the scale, a screen or the resolution changes, but not when only the taskbar's size changes the work area. Hearing that needs a platform signal (`WM_SETTINGCHANGE` with `SPI_SETWORKAREA`) through a port (from P3, 2026-10-10).
- G14 soak test: 4 hours of automatic typing, with no memory growth and no crash (moved here from P1).
- Sign releases with a paid signature (ADR-0030): Azure Artifact Signing (individuals only in the US and Canada), a certificate authority's certificate or the Microsoft Store; any public signature shows the legal name. Until then, releases are unsigned with a clear README.
- Settle how the sold app is delivered and unlocked, and where releases are built and signed, as the licence-key check stays outside the public repository (ADR-0030).
- Ship the Visual C++ runtime with the app (redistributable, or app-local after `kx-licence-check`). Without it, a uiAccess start on a PC that lacks it searches the working folder and `PATH` (found in P3 Task 20).
- The development PC has one screen, so moving the keyboard between two screens with different scaling (G11) is checked by beta testers on their own PCs.
- The tray picture is drawn again only when the scale of its hidden window's screen, the main one, changes. Beta testers check a taskbar on a second monitor, a scale change there, and a switch of the main display (from P3).
- Add a software-drawing option for weak PCs and G8's weak pass. The app reads it from its own settings before `harden` runs, never from Qt's variables (owner, 2026-10-01).
- Type-test Arabic (101) before v1; P3 typed only Arabic (102) AZERTY (2026-10-01).
- Start-up sits at G8's 500 ms budget: 350–788 ms over nine runs on 2026-10-12, median 527, slower under memory pressure. Most of it runs from the log's first line to the guarded windows (about 650 ms); profile it before v1 (from P3, owner's decision).
- After a reboot, PresentMon marked every frame of some G8 presses as never shown (43–49 a run), while G8's own screen copies saw all 20 presses lit within 15 ms. Find which is right (an overlay plane, or PresentMon losing the display events) before trusting `dropped_frames` (from P3, 2026-10-12).
- Fix before beta: the key-press route (`[keyboard] key_apps`) trusts that a dead key then Space types the dead key's own character, which is false on Swiss French, Czech, Slovak, Romanian and a few others. After a cut send that follows a dead key's press, `deliver` in `crates/kx-platform-windows/src/inject.rs` releases the keys still down but never sends the Space, so the dead key stays pending (from P3, 2026-10-01).
- `.cargo/config.toml` gives MSVC `/utf-8` only for x86_64 builds; add the same for ARM (aarch64) builds when they come (from P3, 2026-10-01).
- Before any signed build leaves the development PC, check that per-user COM registrations (`HKCU\Software\Classes\CLSID`) never load into the uiAccess process. On the staged signed build, list the in-process classes it activates with Process Monitor (the owner's yes first), and check that a planted `HKCU` override for each never loads (`docs/security/keyxtend.md`, from P3, 2026-10-02).
  - Play a key sound during the trace, so it covers the classes `XAudio2` activates to open the audio device, the device enumerator among them (from P4).
  - Click Power during the trace, so it covers `Shell.Application` (from P6).
  - Click the clipboard panel's Open folder during the trace, and also plant an out-of-process override (`LocalServer32`, `TreatAs`) for `ShellWindows`, which it activates as a local server (from P8).
- Pin the QML disk cache off in the uiAccess build: `harden_qt` sets Qt's cache option to ahead-of-time units only (check its name in Qt 6.11's docs), and the stage check refuses `.qml`, `.js` and `.mjs` files (from P3, 2026-10-02).
- Release builds trim or remap source paths (Cargo `trim-paths` or `--remap-path-prefix`): a panic inside a dependency logs its source path, which can name the builder's account (from P3, 2026-10-02).
- Check whether Qt's font list in the uiAccess process takes per-user fonts (`%LOCALAPPDATA%\Microsoft\Windows\Fonts`); if it does, try `ProcessFontDisablePolicy`, as long as the bundled fonts still load (`docs/security/keyxtend.md`, from P3, 2026-10-02).
- At release, add everything `THIRD_PARTY.md` asks for: the credit lines (FreeType, Imlib2, and libjpeg if `qjpeg.dll` ships), the Public Suffix List pointer, and a `licenses/` folder with every bundled part's notice, Qt's LGPL texts and a note on swapping its DLLs (from P3, 2026-10-01).
- `Kernel::disabled()` reads the kernel section on every call; cache it if the start-up profile shows it (from P3).
- Notepad drops a few characters right after punctuation in fast G1 bursts, likely its spell-check; keep it in mind for typing tests (from P3).
- Type a few keys with the planted Qt variables of `docs/security/keyxtend.md` set, on the staged signed build; that nothing loads from them is already confirmed (from P3).
- The first switch to a layout no bundled font covers is slow: on CI's cold debug build, Hebrew's keys took 7.4 s to be listed and named, then 3.1 s on the next run, against 0.62–0.68 s for German, Russian and Persian (G26, 2026-10-13). Find the cause, likely Windows' fallback font lookup on the GUI thread, and keep it well under G26's `label_wait_ms` (from P3).
  - It now fails G26 on some CI runs: Hebrew's 48 labels never showed within 77 s on P6's run, 11.8 s on P5's merge and 59 s on a Dependabot run, against the 10 s limit; its typing passed, and other runs passed (from P6, 2026-10-23).
- G10 with the installed NVDA before v1: the keys and top-bar buttons are read and can be pressed. A portable NVDA runs without uiAccess, so Windows keeps it from reading our uiAccess windows; it read the taskbar but no key (P3, 2026-10-12). The README should say that a screen reader needs its installed copy.
- PresentMon saw no display time for about 99 % of frames, ours and other apps', while scrcpy, WSL and Docker ran (2026-10-15); with them closed, every frame showed. Run the frame gates (G8, G12) on a quiet PC (from P4).
- After real use (clicks, typing, resizes, a mode on), private commit sits at 141–142 MB against the 140 MB budget; the owner accepted it as in P3 (from P4, 2026-10-16). The soak decides whether it grows.
- Start-up took 1,176 ms under the owner's WSL and Docker load, 356–384 ms on a quiet PC, and 624 ms on a quiet PC with Arabic in front (from P4, 2026-10-15 and 16).
- G10 presses Caps Lock a second time through `press`, so a guard stop could leave it on, and a failed put-back press leaves a mode flipped (from P4's review; older than P4).
- Beta testers: G12 with two stacked screens (a point on the upper taskbar may land on the lower one), and the overlay when the keyboard is away and the mouse module restarts with Right-click saved on (from P4).
- Check the sounds when the audio device changes or headphones are unplugged while typing; P4's hands-on check did not cover it.
