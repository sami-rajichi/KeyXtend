# P6 — Shortcuts and Power

## Already built

- Layout cycling and Ctrl+C/V/Z, Win+V and Alt+Tab were tested in G25 ([move map, P5 to P12](../spike-move-map.md#p5-to-p12--one-feature-each)).
- Built in P6 (2026-10-23): the shortcuts layer with 37 shortcuts named by meaning, each sent by its platform's own table (Windows' now, macOS and Linux in P15), and the Power key, which opens the system's own power dialog ([plan](../superpowers/plans/2026-10-23-phase-6-shortcuts-and-power.md), ADR-0031).

## Notes

- An injected Win+V needs uiAccess.
- The Power key opens the system's own power dialog and never shuts down directly (spec §8.5).
- `ToUnicodeEx` ignores Win, so Win+key "types" for the adapter and the fake, though the shell takes most Win+key presses. Fake gaps against Windows: Ctrl+Tab, Ctrl+`[` `]` `\`, French Ctrl+à (U+0000), Arabic Ctrl+ك و ز ظ, Ctrl+Alt (the AltGr level) and French Shift+².
- Settled: the French Power key reads «Marche/Arrêt», not «Arrêt», since it only opens the power dialog (owner, 2026-10-23).
- A panic in the platform's power call dims the Power key until KeyXtend restarts, with no notice. The scroll pad dims the same way after its own panic, but its `notice.scroll-stopped` says to restart.
- On-screen tests that flaked in P6's full test runs under load, each passing on rerun; P6 changed none of their code:
  - in `kx-platform-windows`: `scroll::uia::tests::each_way_reads_and_steps_the_first_that_scrolls_along_its_axis`, `window::tests::calls::giving_back_is_a_no_op_while_none_of_ours_is_in_front`, and `window::tests::cross::a_lift_that_does_not_land_during_another_threads_drop_is_made_again_after_it` and `the_checks_end_when_a_lift_never_lands`;
  - in the Qt Quick tests with high-DPI scaling off: one D3D11 driver crash in `QRhi`'s teardown.
- The test certificate and the Program Files test installs stay for the uiAccess gates. The certificate expires on 2026-12-26; the owner decides when to remove it and the spike face's test install (moved from P5).
