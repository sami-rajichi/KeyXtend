# P8 — Clipboard history

## Already built

- The clipboard listener: G20 heard every copy, skipped marked copies and pasted an older copy back ([move map, P5 to P12](../spike-move-map.md#p5-to-p12--one-feature-each)).

## Notes

- New in this phase: the encrypted store, the paged panel, images and files, and the `media` worker for thumbnails.
- Word was not tested in G20 (its sign-in dialog blocked it).
- `kx-crypto` (the DPAPI-protected data key and XChaCha20-Poly1305) is already built: P7 sealed its learned words and emails with it (moved from P8, owner, 2026-10-24). The clipboard store reuses it and its blob store.
- P3 took Space out of the board's panel keys, so the language list lets it type. The clipboard panel ticks with Space (spec §3.3), so it needs a key list per panel in `kx-mod-keyboard`.
- Every clipboard event must set `Event::CAPABILITY`, since the bus's capability gate is opt-in (P3).
- Never test with Word: its sign-in and subscription dialogs block every test, so drop it from G20's targets when this phase aims the gate at the product (owner, 2026-10-16, from P5).
- Win+V routing moved here from P6: with a setting, Win+V from our keyboard opens our history instead of Windows' own (spec §7, Windows only; owner, 2026-10-23).
- An injected Win+V needs uiAccess (from P6).
- Our writes' marker is `CanIncludeInClipboardHistory` = 0, which our watch skips (`Marked`) and Windows' history obeys; `CanUploadToCloudClipboard` = 0 goes with it. Apps that read the clipboard, a remote desktop's included, still get the copy (Task 10).
- The watch reports a copy of formats it does not keep as `Copied` with no parts, so the module hears every change; it must keep no row for it (Task 10, for Tasks 11 and 14).
- Office apps put a picture of copied text beside the text, so a text copy from Excel or Word also carries an image part (Task 10; the module's kind rule decides).
- On-screen-sensitive tests: the `kx-platform-windows` clipboard tests (`clip::tests::live`) write the real clipboard behind one test lock; a copy made in another app during the run can make one fail, so rerun it alone once before calling it a failure.
