# P8 — Clipboard history

## Already built

- The clipboard listener: G20 heard every copy, skipped marked copies and pasted an older copy back ([move map, P5 to P12](../spike-move-map.md#p5-to-p12--one-feature-each)).

## Notes

- New in this phase: the encrypted store, the paged panel, images and files, and the `media` worker for thumbnails.
- Word was not tested in G20 (its sign-in dialog blocked it).
- `kx-crypto` (the DPAPI-protected data key and XChaCha20-Poly1305) is already built: P7 sealed its learned words and emails with it (moved from P8, owner, 2026-10-24). The clipboard store reuses it and its blob store.
- P3 took Space out of the board's panel keys, so the language list lets it type. The clipboard panel ticks with Space (spec §3.3), so it needs a key list per panel in `kx-mod-keyboard`.
- Every clipboard event must set `Event::CAPABILITY`, since the bus's capability gate is opt-in (P3).
- Never test with Word: its sign-in and subscription dialogs block every test, so drop it from G20's targets when this phase aims the gate at the product (owner, 2026-10-16, from P5).
- Win+V routing moved here from P6: with a setting, Win+V from our keyboard opens our history instead of Windows' own (spec §7, Windows only; owner, 2026-10-23).
- An injected Win+V needs uiAccess (from P6).
- Our writes' marker is `CanIncludeInClipboardHistory` = 0, which our watch skips (`Marked`) and Windows' history obeys; `CanUploadToCloudClipboard` = 0 goes with it. Apps that read the clipboard, a remote desktop's included, still get the copy (Task 10).
- The watch reports a copy of formats it does not keep as `Copied` with no parts, so the module hears every change; it must keep no row for it (Task 10, for Tasks 11 and 14).
- Office apps put a picture of copied text beside the text, but the watch never fetches an image while non-blank text is there, so that picture is neither rendered nor counted toward `TooBig` (Task 10).
- A path whose drive does not answer is `FileFact::Away`: its row stays and an insert skips it, while `Gone` comes only from a drive that answers (Task 10, for Task 14).
- Only an absolute drive path (`C:\…`) is looked at, through `probe_ok`; a share, device, NT or relative path, or one through a symlink or junction, is `FileFact::Unchecked`, shows "Size unknown" and pastes at insert (security check).
- `TooBig`'s byte count stops once it passes the cap, so it is "at least" that many bytes (Task 10).
- On-screen-sensitive tests: the `kx-platform-windows` clipboard tests (`clip::tests::live`) write the real clipboard behind one test lock, and run only with `KX_LIVE_CLIPBOARD=1` set, as CI does. A copy made in another app during the run can make one fail, so rerun it alone once before calling it a failure.
- Hands-on check: copy images from Paint, a browser and Snip, and look at each thumbnail and preview, above all V4 and V5 DIBs with bit masks, whose masks some writers repeat after the header (from the worker's security note). Then take a Snip screenshot, insert it into Paint and check the picture arrives whole: Insert sets its PNG with the `CF_DIB` the worker makes (final fix 2).
  - With `history_key` off (P13's Settings, or by hand on a test profile), Win+V from our keyboard opens Windows' own panel on the dev install; G20 skips this part on the test build, which has no uiAccess.
- A file row shows Lucide's plain `file` icon and a text row `file-text`, so the two kinds no longer share one icon (owner, final fix).
- Later improvements found while building P8:
  - A file path is stored as UTF-8, so a Windows name that is not valid Unicode reads back with U+FFFD, looks gone and may drop its row at insert; accepted as rare.
  - The clip key does not dim while the clipboard module is off, as the keyboard does not yet listen to the kernel's ungated `ModuleStateChanged` for it, so a click then does nothing.
  - Paging the preview's long text with the scroll pad needs a new module act; today it pages by its own buttons only.
  - One `SecretStore` gates both the word store and the clipboard's shelf; a gate per store would need a new ADR (`docs/security/kx-crypto.md`).
  - File facts ask each drive's root once, so a root that denies access makes its paths away (Task 10 review). A path through a junction is now unchecked, never followed.
  - A drive letter mapped to a share (`Z:\`) is still looked at; telling it apart needs the drive's type in the Windows adapter (security check).
  - Tidy F4 reads one line at a time: it flags a rename of `std::process`, but a rename split over lines slips past; clippy's `disallowed-types` could back it (Task 9 review).
  - A skipped app's copy is still read in full by the watch before the module drops it; naming the owner first and handing the adapter the skip list would make it "never read" (final review).
  - The watch's marker check can hold the clipboard just as the target app pastes, so an app that tries only once pastes nothing; waiting for the watch's `Marked` note, up to `paste_wait_ms`, before `PasteAsk` would close it (final review).
  - A file entry's preview puts every path in each view's JSON, so a copy of thousands of files makes each wake parse a large text; the hub could send only the shown page and the count (final review).
  - An image preview opened while the picture worker rests shows its type icon, and draws only when opened again after the rest (final fix).
  - An insert's DIB ask waits behind any thumbnail or preview the worker is drawing, so a busy worker can miss `media_ms` and the PNG then goes alone; asking the DIB ahead of draws would close it (final fix 2).
