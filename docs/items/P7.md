# P7 — Word prediction

## Already built

- Password-box detection: G21 flagged password boxes in Chrome and Win32 apps ([move map, P5 to P12](../spike-move-map.md#p5-to-p12--one-feature-each)).

## Notes

- New in this phase: the prediction engine, the learner, `@` domains and saved emails; the word lists need `kx-licence-check`.
- Every typed-text event must set `Event::CAPABILITY`, since the bus's capability gate is opt-in (P3).
- `KeyboardFaceKey` carries no capability (`crates/kx-module-api/src/ports/face.rs`), yet `FaceAction::Tap` injects keys, so any module that requires the face could type. Before another module requires it, decide in an ADR between a dedicated capability and a read-only face split (from P3, 2026-10-01).
- `InputInjector::text` takes text of any length and sends two inputs per UTF-16 unit in one batch; P3 sends one key's text, at most 32 units. Cap it from the settings schema before this phase types words (`docs/security/kx-platform-windows.md`, from P3, 2026-10-02).
- The memory check's churn turns Caps Lock over through `FaceAction::FlipCaps`, a debug-only variant of the module API's public enum, so its shape depends on the build kind. Before this phase opens the face to other modules, wrap the layout-source port in the composition root so a debug flag turns `caps_on()` over, have the churn send `relabel()`, and drop the variant (review B2 N2, from P3, 2026-10-11).
