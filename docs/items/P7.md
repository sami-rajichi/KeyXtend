# P7 — Word prediction

## Already built

- Password-box detection: G21 flagged password boxes in Chrome and Win32 apps ([move map, P5 to P12](../spike-move-map.md#p5-to-p12--one-feature-each)).

## Notes

- New in this phase: the prediction engine, the learner, `@` domains and saved emails; the word lists need `kx-licence-check`.
- Every typed-text event must set `Event::CAPABILITY`, since the bus's capability gate is opt-in (P3).
- `KeyboardFaceKey` carries no capability (`crates/kx-module-api/src/ports/face.rs`), yet `FaceAction::Tap` injects keys, as do `Press`, `Tick` and `LetGo` since key repeat, so any module that requires the face could type. Before another module requires it, decide in an ADR between a dedicated capability and a read-only face split (from P3, 2026-10-01).
- `AssistNote` and `PointerMoved` carry click points, and neither names a capability, so any module could hear them (`docs/security/kx-mod-mouse.md`, Accepted). Decide their gate together with the face's (from P4's review, 2026-10-14).
- `InputInjector::text` takes text of any length and sends two inputs per UTF-16 unit in one batch; P3 sends one key's text, at most 32 units. Cap it from the settings schema before this phase types words (`docs/security/kx-platform-windows.md`, from P3, 2026-10-02).
- Done on 2026-10-25 (Task 13): the memory check's churn flips a debug flag that a layout-source wrapper in the composition root reads, and the debug-only `FaceAction::FlipCaps` is gone (review B2 N2, from P3, 2026-10-11).
- Hold-to-fill (spec §6) meets key repeat (§4.6, from P3, 2026-10-11): P and the key that types @ (with Shift or AltGr, by layout) are character keys, so a hold repeats them after `repeat_delay_ms` (0.8 s by default), before hold-to-fill's 1.5 s. Decide here whether a hold on those two keys fills or repeats, and keep every other key repeating; the vault's lists come from P9.
