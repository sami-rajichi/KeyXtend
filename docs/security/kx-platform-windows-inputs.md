# Security note: kx-platform-windows, inputs from outside

A detail section of [kx-platform-windows.md](kx-platform-windows.md), which keeps the scope, capabilities, data, threats and findings. Each row is one input the adapter takes from files, IPC, OS callbacks, the clipboard or the network.

| Input | Validation | Size/time limit | Fuzzed |
|---|---|---|---|
| `SHGetKnownFolderPath` (Local AppData) | Error mapped to `PlatformError::LocalData`; the path is taken as UTF-16 as Windows gives it, never through `TEMP` or other environment variables | Windows bounds the string; it is copied once and freed once | No |
| `current_exe` (program path) | A path with no folder is refused (`NoExeDir`), so the portable `data` check never runs in the working folder | N/A | No |
| `QueryPerformanceFrequency` / `QueryPerformanceCounter` | Frequency failure refused at start-up; tick maths in 128 bits, clamped, negative and zero values handled (property tests) | N/A | Property tests |
| `CoInitializeEx` result | Success pairs one `CoUninitialize` on the same thread (`Com` is not `Send`); another thread mode is accepted and never undone | N/A | No |
| `Shell.Application` and `ShutdownWindows` (`power`) | Each open starts an apartment-threaded `Com` on its calling thread, makes the object in-process and releases it before COM stops; no shell object reads as `Unavailable` and a refused call as `Failed`, never a panic | One object and one COM start per open | Fake-OS tests of the rule; a real test only makes the object |
| Our own process token (`TokenUIAccess`) | Reads 4 bytes (`size_of::<u32>()`) into a `u32`; any failure reads as "no uiAccess" | Fixed size | No |
| A started worker's token, read back (`worker::access::rights`) | `TokenUIAccess` into a `u32`; `TokenIntegrityLevel` into a buffer of the label and the largest SID, whose SID passes `IsValidSid` before its last part is read; `TokenGroups` and `TokenPrivileges` into a pointer-aligned buffer of the size Windows asks, each list read only within it (`listed`). A worker with uiAccess, above Medium, able to use Administrators or holding any privilege but change-notify, even disabled, is ended before it runs (`SpawnError::Rights`), and a token that cannot be read fails the start | The lists within their buffer | Real tests on the started worker and the token made for it; pure tests of the verdict and the list reader |
| A drive's free bytes and volume root (`disk`) | `GetDiskFreeSpaceExW` and `GetVolumePathNameW` read the folder the app names, the nearest one that exists; the root is read up to its first NUL into a buffer of at least the path's length and `MAX_PATH`, and shown without its last backslash. A folder on a share would be reached too, but the app names only its history folder, inside its own data folder | One `u64`; the root within the buffer | No: Windows' own answer, tested on the real drive |
| Copied file paths, before any look (`clip::facts`) | Only an absolute drive path such as `C:\…` passes `probe_ok`; every other form, a share (`\\host\`), a device or NT path (`\\?\`, `\\.\`, `\??\`), a relative path or a bare `C:foo`, is `FileFact::Unchecked` with no filesystem call. Each folder from the drive down and the path itself are read with `symlink_metadata`, so a path through a symlink or junction is Unchecked and never followed | Each drive, folder and path looked at once per batch, on the files thread | Pure tests over fake looks; a real file, a real symlink on Linux, and a real junction (`mklink /J`) on Windows, looked through and at |
| The worker's path (`worker`) | Only `keyxtend-worker.exe` beside the running program (`current_exe`), absolute and a file, else `Missing`; it goes to `CreateProcessAsUserW` as the application name, so no search path is used | N/A | Unit test |
| The worker's console (`worker::start`) | Started with `DETACHED_PROCESS`, so it has no console: a console host would run under the worker's token, load `user32` and fail where that token reaches no desktop, as on CI's UAC-off runner (`0xC0000142`) | No process besides the worker | Real test: the started worker has no child process |
| The worker's replies (`worker`, read by `kx_platform::worker`) | `kx-ipc` checks each frame; the host refuses a reply to another ask, of another kind or, for a draw, pixels that are not the size asked (`Pixels::new`), then ends the worker (`kx-platform.md`) | One frame at a time, within `deadline_ms` | Property tests in `kx-ipc`; scripted host tests |
| Session and power messages to the session watch's top-level window (`session`, P11) | Only the message and wParam pairs `session.toml` lists map to a note, each told once in a row; any other passes to Windows. The window is never shown and takes no activation (`WS_POPUP` without `WS_VISIBLE`, `WS_EX_NOACTIVATE`), and a panic in the callback is caught before Windows. Another program can post the messages (see Accepted in [the note](kx-platform-windows.md#accepted-with-reason)) | One note per message | Pure tests and a live test that posts each message and checks the window stays hidden (`session::win::tests`) |
| A card's name from the engine, matched to DXGI's adapter names (`voice::cards`, P11) | Compared whole, case aside; no match gives no driver (see Accepted in [the note](kx-platform-windows.md#accepted-with-reason)), and the version is four numbers from DXGI | One walk of the adapters per call | Unit tests |
| Model files the models host fingerprints (`voice::disk::print`, P11) | Opened with `FILE_FLAG_OPEN_REPARSE_POINT`, so a link or junction is never followed, and refused unless it is a plain file; shared with readers only, so no program writes it meanwhile, and refused when the bytes read or its size at the end differ from its size at the start | 1 MiB read at a time | Real-disk tests (`voice/disk/tests.rs`) |
| `places.toml` and `redirect.toml` | Adapter tables built into the app, never read from disk. Both parse strictly and tests prove the shipped pair parses. A broken places table suggests and finds nothing, with every other call `Io`; a broken package table makes each probe under the app-data folder, list and delete `Unreadable`, so nothing is deleted | Fixed at build time | Unit tests of each refusal |
| Cloud folders from the environment, labels and parts (`places`) | The table's environment variables, known folder parts and volume labels only; no cloud app's config is parsed. A relative or missing folder is not offered | The table's list | Unit tests (`places/tests/suggest.rs`) |
| Drives and folders Windows lists (`places`) | Only `DRIVE_REMOVABLE` is suggested, so a USB hard disk is reached through the folder list. A network drive leads the folder list but is never suggested or searched (`a_network_drive_leads_the_folder_list_but_is_never_suggested_searched_or_a_cloud_base`). Hidden, system and junction folders are left out, and a linked box is never taken | `max_listed`, `max_subfolders`; `Quiet` turns Windows' drive dialogs off for the calling thread (`SEM_FAILCRITICALERRORS`) | Real-disk tests (`places/tests/`) |
| A place the user picks (`places`) | The data folder, above or below it, however spelt or reached, is `Refused`, as a format would wipe it (`the_data_folder_its_parents_and_children_are_refused_however_spelt_or_reached`) | One check per pick and write | Real-disk tests |
| A box or KeePass file's bytes on disk (`places`) | Its size first, without read access, and then a read of one byte past the cap at most, so a file that grew is refused too (`a_read_over_the_cap_is_refused_before_the_file_is_opened`) | The cap the module gives; `box_mb` or `MAX_KEEPASS_BYTES` | Real-disk tests |
| Package folders under the local app-data folder (`redirect`) | A probe only runs when the data folder lies under the local app-data folder. Each mirror is read through the neutral rules (`kx_platform::mirror`); links are left out and `remove` takes only a copy listed now, never the data folder | One probe at start; a remove on the user's click | Real-disk tests (`redirect/tests.rs`) |
| `SendInput` count | Clamped to the batch length; a batch too long for a `u32` is not sent | One batch per call | Property test of the release rule |
| `VkKeyScanExW` answer | Only no modifier, Shift, Ctrl+Alt (`AltGr`) or Shift+Ctrl+Alt is typed, and anything else is `Unmappable` before a key is sent; `AltGr` goes as a physical one does, left Ctrl then right Alt with the extended flag. `ToUnicodeEx` (the layout source's reader, no state change) must confirm the key types the character under the current Caps Lock, in that Shift state or the other; a dead key must give the character as its own, and Space follows it | Fixed size | Unit tests of every bit; fake-layout tests; a real AZERTY test |
| `MapVirtualKeyExW` scan code | Only its low byte and prefix byte are read | Fixed size | Unit tests |
| The compiled-in `shortcuts.toml` and `keynames.toml` (`shortcut`) | Adapter tables built into the app, never user input: the settings name only ids. | A shortcut's layout and keys: `GetKeyboardLayout` (the app in front's, else the calling thread's own) and `MapVirtualKeyExW` (`shortcut::plan`) | Plain queries that send no message; each step's keys are the table's virtual keys with the scan code that layout gives, the latched scans join each step once (`once_each`), and the batch goes tagged `TAG` like the injector's | One batch per click, at most the table's steps | Unit tests over a fake OS (AZERTY, latches, chains, a refused send); a property test that every plan is balanced and presses each key once (`shortcut/tests/props.rs`); real-layout tests that plan and never send |
| `LockWorkStation` (`shortcut::win`, Lock PC only) | Only its success is read; a refusal is `ShortcutError::Failed`, which the keyboard shows as the keys-not-sent notice. It only starts the lock and returns | One call per click | A test plans the call; none makes it |
| The history chord: the table's `history` keys, its scan codes in the app in front's layout, else our own (`shortcut::history`) | Plain queries that send no message; the held scans and the key must equal the chord exactly, and a table with no chord or a broken one never matches or is refused | One check per click while the clipboard module wants the chord | Fake-OS tests (AZERTY, our own layout, no chord, a broken one); a real-layout test over each installed layout |
| `GetKeyboardLayoutList` | Asked for the count first, then filled into a buffer of that count, so there is no cap; the copy is cut to what Windows wrote | Windows' own count | Fake-OS tests (40 layouts, a list that shrinks) |
| `ToUnicodeEx` / `MapVirtualKeyExW` | Called only for an installed layout or the layout of the app in front; flag `0x4` leaves every keyboard state as it is; the count is clamped to a 32-unit buffer and its sign read as a dead key; controls read as empty | 32 UTF-16 units per key | Unit and property tests of the answer reader |
| Registry `HKLM\...\Keyboard Layouts` (`Layout Text`, `Layout Id`) | Read-only key, `REG_SZ` values only, into a 128-unit buffer; the size Windows writes back is clamped and cut at the first null; `Layout Id` must be hex; the key is closed once | 128 UTF-16 units per value; the variant search ends at the first enumeration error | Unit and property tests of the text, id and key-name readers |
| `LCIDToLocaleName` / `GetLocaleInfoEx` | Fixed buffers; counts clamped; a number is read from exactly two units | 128 UTF-16 units | Unit and property tests |
| `GetGUIThreadInfo` (window with the keyboard) | A failed call or no focus falls back to the front window; thread 0 is refused | Fixed size | No |
| `QueryFullProcessImageNameW` (app in front) | Buffer of the Windows path limit; the length Windows writes back is checked; invalid UTF-16 reads as unknown; the process handle is closed once | 32,767 UTF-16 units | No |
