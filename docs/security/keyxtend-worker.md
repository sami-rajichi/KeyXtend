# Security note: keyxtend-worker

- **Owner:** product owner
- **Last review:** 2026-11-20 (T23 fix wave: Base64 through the `base64` crate, a run's texts capped together, error replies read once, and the speech-net job's leftovers in std's buffers, the boundary's hasher and WinHTTP accepted); 2026-11-20 (P11 part 2 task 22: the `speech-net` job added from the code and the task 8, 18, 19 and 19b reports); 2026-11-16 (P11 task 29 `kx-security-check`: the `voice` and `fetch` jobs final). Earlier reviews are in git.
- **Status:** Reviewed
- **Scope:** `apps/keyxtend-worker`, the program with five jobs so far, outside the uiAccess keyboard (ADR-0004).
  - `keyxtend-worker media --max-pixels <n>` decodes copied PNG and DIB images into small RGBA thumbnails, and makes a `CF_DIB` from an inserted PNG (ADR-0034 decision 5).
  - `keyxtend-worker vault` makes backup padlocks, seals, opens and checks backup boxes, and reads KeePass files (P9, ADR-0038 decision 6).
  - `keyxtend-worker voice` records the default microphone, tells levels, cuts pieces at pauses and hands its recording over, with no network (P11, ADR-0042). It writes text with `transcribe.cpp` and finds speech with Silero, both on this PC (P11 task 12); a build without the `engine` feature answers `Runner`.
  - `keyxtend-worker fetch` downloads one model file at a time over HTTPS into `<file>.part`, and names it only once its size and SHA-256 pass, with no microphone (P11 task 13, ADR-0042, ADR-0043 decision 8). `kx_platform::models` runs one such job per download (P11 task 14).
  - `keyxtend-worker speech-net` sends a cloud dictation's pieces, or a key's test, to the one service its ask names, over HTTPS with no redirect, and tells each piece's text in order, with no microphone (P11 part 2, ADR-0047, ADR-0051). `kx_platform::cloud` runs one such job per run or key test.
  - The hosts in `kx_platform::pictures`, `boxes`, `speech`, `models` and `cloud` start it on demand, through the adapter's spawner with lowered rights (`kx-platform.md`); the OCR and update jobs come later.

## Capabilities
| Capability | Why needed | What breaks without it |
|---|---|---|
| None | It reads asks on the stdin and writes replies on the stdout it is given, and opens no pipe or window. The voice job reads the model, detector and clip the host names; the fetch job writes only the part the host names and renames it. The `Pictures` port it serves needs no capability (ADR-0034 decision 3); the `Boxes` port's gate, `VaultData`, is the module's and is checked inside the keyboard (ADR-0039). | N/A |
| The microphone (voice job) | The `voice` job opens the default input device through `cpal` while a run listens. `Microphone` is the speech port's gate, checked inside the keyboard (ADR-0042 decision 8). | Dictation |
| The graphics card (voice job, `card` build) | A model the host aims at a card runs there through Vulkan (`ggml-vulkan.dll`); anything else runs on the processor. | Fast dictation; the processor still serves |
| The network (fetch job) | HTTPS GETs through WinHTTP (`kx-platform-net`), only to the hosts the ask lists: a first address to one listed by name, a redirect also to one under a listed `.` domain. `Network` is the model files port's gate, checked inside the keyboard (ADR-0042 decision 8). | Model downloads |
| The network (speech-net job) | HTTPS POSTs through WinHTTP (`kx-platform-net`), only to the one address the ask names: the service row's host, or the typed Custom host, as the module and `kx-ipc` checked. A redirect is never followed. `Network` is the cloud port's gate, checked inside the keyboard (ADR-0047 decision 11). | Cloud dictation |

## Data handled
| Data | Class (Secret/Sensitive/Public) | Stored where | Encrypted | Retention |
|---|---|---|---|---|
| Image bytes in a `Draw` or a `Dib` ask (copied by the user) | Sensitive | Memory only | No; only the host and the worker hold the pipe | Dropped before the reply is written |
| Pixels in a `Pixels` reply, a DIB in a `Dib` reply | Sensitive | Memory only | No | Until the reply is written |
| A backup or KeePass password (vault job) | Secret | Memory only: `Wiped` in the frame, wiped with the ask; the last raw frame also stays in std's stdin buffer (see Accepted) | No | One ask, then until the next frame overwrites it |
| A box's notebook part, opened or to seal | Secret | Memory only: `Zeroizing` in the reader and the replies; at seal, `age`'s stream keeps up to 64 KiB of it unwiped (see Accepted) | Sealed before it leaves; opened only inside the job | One ask |
| A padlock's recipient and locked identity | Sensitive: the identity opens only with the password | Memory only | The identity by scrypt | One ask |
| A box's sealed bytes and a KeePass file's bytes | Sensitive: locked until opened | Memory only | `age` or KDBX | One ask |
| A KeePass file's entries | Secret | Memory only: our copies are wiped when dropped; `keepass` leaves unprotected values and its XML unwiped (see Accepted) | No | One ask |
| Sound: the microphone's chunks, the recording, pieces for the engine, hand-over and hand-in pieces (voice job) | Secret | Memory only, in wiped buffers that grow by copying and wiping the old one (`voice/wipe.rs`) | No | The recording until Close, a new Start, goodbye or the end of input; chunks and pieces until used |
| Text: the engine's pieces and a check's two texts (voice job) | Secret | Memory only: `Zeroizing` strings with room for a whole note from the start, so they never move; the engine's other copies in its Rust result are wiped (`a_kept_text_leaves_no_other_copy_of_the_words`); `transcribe.cpp`'s own buffers are not (see Accepted) | No | Until its note is written |
| A download's addresses and hosts (fetch job), from the models table; a redirect's address may carry a signed query | Public | Memory, for one download; never logged, and no note or fault holds one | N/A | One download |
| Model file bytes (fetch job) | Public (untrusted data) | `<file>.part` in the models folder, then the named file once checked | TLS in transit | Until the user deletes the file |
| A cloud service's key (speech-net job) | Secret | Memory only: `Wiped` in the frame, then the request's header lines in a wiped buffer (`kx-platform-net.md`); the last raw frame also stays in std's stdin buffer, and WinHTTP keeps its own copy (see Accepted); never in a note, a fault, a log or stderr | TLS in transit | One run or key test |
| Sound: hand-over pieces, each piece's WAV and its request body (speech-net job) | Secret | Memory only, in wiped buffers each sized once: the WAV header and piece (`net/wav.rs`), the form's body under its boundary (`net/multipart.rs`), or Gemini's JSON with the Base64 written straight in, chunk by chunk through the `base64` crate's `encode_slice` into a wiped buffer, never its unwiped `Base64Display` (`net/base64.rs`). std's stdin buffer, the boundary's hasher and WinHTTP keep a little (see Accepted) | TLS in transit | Until its piece's request ends |
| A service's reply and the texts read from it (speech-net job) | Secret: untrusted | Memory only: the body read within `MAX_NET_REPLY_BYTES` into a wiped buffer, its `text` read straight into a wiped string; `serde_json`'s own scratch is not wiped (see Accepted) | TLS in transit | Until its note is written |

The worker never logs. Only the fetch job writes to disk: the part the host names and its rename, never a folder. The voice job turns `transcribe.cpp`'s log off before loading anything, as a line may name a path. Its replies give a fixed reason (`Why` or `Fault`), never decoder text.

## Threats (STRIDE-lite)
- **Spoofing:** the worker trusts only its own stdin, an anonymous pipe the host hands to its child (task 9). Each reply repeats its ask's id, so the host can refuse a stray answer (`serve` tests).
- **Tampering:** a crafted image targets the decoder.
  - PNG goes through the `png` crate and its inflater `fdeflate`, both `#![forbid(unsafe_code)]`; only the checksum crates (`crc32fast`, `simd-adler32`) use SIMD code.
  - The DIB reader is ours, safe Rust, with every field, offset and size checked: `other_header_sizes_are_refused`, `rows_past_the_buffer_are_refused`, `huge_fields_never_overflow`, `masks_that_are_not_distinct_whole_bytes_are_refused`.
  - Each ask runs under `catch_unwind`, so a panic is a `Failed` reply with `Internal`, and the loop goes on (`a_panic_is_an_internal_failure_and_the_loop_goes_on`, `a_dib_ask_gets_its_dib_and_a_refused_or_panicking_one_a_failure`).
  - The DIB it makes is 32-bit `BI_RGB` after a `BITMAPINFOHEADER`, rows bottom-up, BGRA with alpha kept, never past the ask's cap (`a_small_png_becomes_its_exact_dib`, `a_dib_past_the_cap_is_too_big_and_one_at_it_is_made`, `the_cap_is_checked_before_any_row_is_decoded`). The keyboard checks only its length and sets it on the clipboard as it is, never parsing it.
  - A crafted model file targets `transcribe.cpp` and `ggml`, C++ code that runs only here. A Rust panic on the engine's thread is an `Internal` fault and the thread goes on (`a_panicking_library_tells_an_internal_fault_and_the_engine_goes_on`); a C++ crash ends the worker, and the host answers its note.
  - A crafted box or KeePass file targets `age` or `keepass`, whose code runs only here. Every vault ask runs under the same `catch_unwind` and silent hook, and a reply past its frame's caps is `TooLarge` (`vault.rs`, `fit`).
  - A swapped or redirected download (fetch job, edges 20 and 22): a redirect to an unlisted host or to plain HTTP is refused before it is asked (`fetch/tests/hosts.rs`), and so is a first address whose host only a `.` entry covers (`kx-platform-net.md`). The file gets its name only once its length on disk and the SHA-256 of every byte written match the row. A bad size or fingerprint deletes the part (`a_bad_fingerprint_deletes_the_part_and_names_nothing`, `a_server_size_other_than_the_rows_deletes_the_part`); a cut, paused, stalled or cancelled download never leaves a named file (`fetch/tests/stop.rs`). A checked part never replaces a file: a name taken at the start or meanwhile is `Disk`, the part waits, and a Cancel deletes it (`a_name_already_taken_is_never_replaced`). A panic in a step is an `Internal` fault and the loop goes on.
  - A hostile or swapped service reply (speech-net job): the body is capped, read by small readers that take any bytes, and its text is told only to the host, which caps a run's texts again (`kx-platform.md`). A redirect, such as a hotspot's sign-in page, is never followed and reads as a strange reply.
- **Logging / repudiation:** no logging. Stderr gets one line for a refused command line or a broken frame, naming only the kind of error. Every job installs a silent panic hook, so a caught panic writes nothing: no message, place or backtrace (`a_hushed_panic_writes_nothing_on_stderr`).
- **Information disclosure:** content stays in memory and on the two pipes. Only the fetch and speech-net jobs reach the network, through `kx-platform-net` (ADR-0042 supersedes ADR-0004's voice line, ADR-0047). The fetch job holds no user content, sends no cookie or credential, and never logs an address, as a redirect's may carry a signed query. The vault job reads no file itself: the keyboard reads each box and KeePass file and hands over the bytes. Debug output never shows a value (`kx-ipc.md`).
  - The voice job never logs sound or text and writes no file; sound leaves only as `Sound` notes after a listen-only Stop or a Keep. ADR-0042 takes the network from it, and tidy F5 keeps the network crate out of its files.
  - A cancelled run's late engine notes are dropped, so no text follows a Cancel (`a_cancelled_engine_tells_no_more_text`). A dropped writer aborts the engine's call in flight and tells nothing more (`a_dropped_writer_tells_no_piece_and_no_end`).
  - The engine and the detector run on this PC; `transcribe-cpp` has no network code, and the `voice` job depends on no network or TLS crate.
  - The speech-net job sends the sound and the key only to the address its ask names, the key only in its header, and never logs either. It never hears the microphone: tidy F5 keeps `cpal` and the engine out of `src/net`.
- **Denial of service:**
  - A decompression bomb is refused from its header: `too_many_pixels_are_refused_from_the_header_alone`, `a_declared_size_past_the_limit_is_always_too_big`.
  - No full-size copy of an image is ever held, so a large image stays within the worker's memory: PNG rows and DIB rows go one at a time into a box filter that keeps the output and one row of sums (`a_large_image_scales_holding_only_the_output_and_one_row_of_sums`, `a_large_png_is_read_row_by_row_within_the_decoder_budget`, 8000 × 6000).
  - Peak memory is the ask (kx-ipc's read holds at most `READ_TIMES`, 2, times it while its buffer grows, up to 64 MiB of image), the decoder's rows (≤ `DECODE_BYTES` counted, plus a few raw rows each at most twice that row), the output (pixels ≤ 64 MiB, or a DIB ≤ its cap, `max_entry_mb`) and the sums (≤ 128 KiB). The settings check refuses a `worker_mb` below `READ_TIMES` times `max_entry_mb`, plus the larger of a preview's RGBA and that DIB, plus `WORKER_BASE_MB`: `DECODE_BYTES` and 16 MB for the worker itself. Both constants come from `kx-ipc`, so the check follows the worker; the job object's cap ends a worker past `worker_mb` (512 MB), and the host restarts it (task 9).
  - Time grows with the pixels, at most `max_pixels`; the host's deadline (`media_ms`) stops a slow draw or DIB (task 9). The worker and its decoder run optimised in dev builds too, so a debug build meets that deadline.
  - The vault job's memory is capped by its own job limit, `VAULT_MEMORY_MB` (1344: 1 GiB of scrypt at the top work factor, boxes at most four times `MAX_BOX_BYTES`, and headroom). A crafted KeePass KDF is refused before it costs memory, and its time ends at the host's `vault_ms`.
  - The voice job holds one run and one recording at a time, stopped at `record_max_s` (`the_limit_stops_the_run_at_exactly_record_max_s`). Every sound buffer grows with `try_reserve`, so the job cap gives a `Memory` fault, not an abort: the host caps a job with a model at the row's `cpu_mb` plus `job_mb` plus twice the longest recording's bytes, one without a model at `job_mb` plus that room, and a check or a file's facts at `job_mb` plus the model's memory or the file's size (`kx-platform` `speech/job.rs`).
  - A microphone opening hands over at most `record_max_s` plus one second of its sound, so a job stalled on a full pipe queues no more than its run could record (`a_stalled_job_queues_no_more_sound_than_its_run_can_record`).
  - One job serves one model file and holds one loaded model; a card's check runs alone and drops it first. A card short of room is refused before loading, and a card that fails hands the same sound to the processor (edges 24, 25).
  - Again cuts a held recording 5 s per turn of the job's loop, so an hour's recording never holds back an ask or a note for long, and Cancel stops the cutting (`a_cancel_between_two_stretches_is_answered_at_once_and_stops_the_cutting`).
  - The fetch job takes one step at a time between asks: one 64 KiB read, one read-back of the part, or one address asked. Each network wait ends at `stall_s` (`a_stall_past_stall_s_is_a_fault_that_keeps_the_part`), reads stop at the row's size (`reads_stop_at_the_rows_size`), and progress is told about 200 times a file, at least 1 MiB apart (`progress_is_paced_not_told_per_read`), the first at once when a Get starts. It holds one download, one 64 KiB buffer and one request, and ends when the host's pipe closes (`a_host_that_goes_away_mid_download_ends_the_loop_and_names_nothing`).
  - The speech-net job paces each run's requests within the row's `per_min` and runs at most `at_once` at a time, so a dictation never floods the link or the service. Each reply stops at `MAX_NET_REPLY_BYTES`, and the host caps the job's memory for its sound and replies (`kx-platform.md`).
  - The host resolves `threads` against the cores Windows lists (`WinHardware::cores`), and the worker takes that count, capped only at the `threads` setting's top (`kx_ipc::THREADS`); a 0, which no resolving host sends, means its own CPUID count (`threads_zero_is_the_real_cores_and_the_hosts_count_is_taken`).
- **Elevation:** the worker runs in its own process from a restricted token: no privilege but change-notify, Administrators deny-only, no uiAccess, Medium integrity (task 9). `#![forbid(unsafe_code)]`; its dependencies are `kx-ipc`, `png`, `age`, `keepass`, `zeroize`, `thiserror`, `transcribe-cpp` (pinned to 0.4.1, with its `-sys` crate, behind the `engine` feature), `kx-platform-net` (the fetch and speech-net jobs' HTTPS, WinHTTP on Windows; its `fake` feature only in tests), `sha2` 0.11 (already in through `keepass`; the fetch check and the form's boundary), `serde` and `serde_json` (the speech-net job's JSON, already in the app) and, on Windows, `cpal` (with `windows` and `dasp_sample`), with theirs: no other `kx-platform*`, no `kx-mod-*`, no TLS or HTTP crate. `cpal`'s, `transcribe-cpp`'s and `kx-platform-net`'s own unsafe code reaches WASAPI, the C++ engine and WinHTTP; the worker has none. Fetch and net files name neither the audio crate nor the engine, and voice files never name the network crate: tidy F5 (`[workspace.metadata.tidy] apart`) fails a file of `src/fetch`, `src/net` or `src/voice`, its `.rs` file included, that names one outside comments and literals. Tidy bans `png`, `fdeflate`, `age`, `keepass`, the engine, `cpal` and `kx-platform-net` from the uiAccess app's tree (`nothing_the_app_builds_with_reaches_a_decoder_a_box_format_a_voice_crate_or_the_worker`). A compromised worker still runs as the user, with the user's SID, minus the job's limits and the restricted token, so it could reach the user's own files; the host checks only the replies it reads (`kx-ipc`, then `Pixels::new` or a DIB's length).
  - Its job object caps its memory at its job's cap (`[clipboard] worker_mb`, `VAULT_MEMORY_MB`, the voice host's sum, a download's `job_mb`, or a cloud run's `job_mb` plus its sound and replies), takes no second process, bars it from shared UI such as other programs' windows and the clipboard, and ends it with the keyboard (`kx-platform-windows.md`, Elevation (worker)).
  - The stage ships it beside the program and refuses a worker that is missing or whose manifest asks for uiAccess (`dev-tools.md`).
  - The stage builds it with `[workspace.metadata.stage] worker_features` (`card`), which never turn `gate` on (`the_stage_builds_this_worker_with_its_own_features_and_never_its_gate`), and refuses any staged or signed program holding the gate's flag, kx-ipc's `SOUND_FLAG` (`a_worker_holding_the_sound_flag_is_refused`, `the_gate_flags_are_the_apps_own_and_the_sound_flag`); a plain build refuses it too (`a_build_without_the_gate_refuses_the_sound_flag_the_stage_refuses`). ### Accepted (with reason)
- Interlaced PNGs are refused: their seven passes cover the whole image, so drawing one needs a full-size buffer, which the row-by-row decoders never hold. Apps rarely copy interlaced PNGs; the history row keeps its type icon.
- Colour profiles, gamma and DIB colour spaces are ignored; pixels are taken as sRGB, which suits a thumbnail.
- 32-bit DIB alpha is taken as straight, not premultiplied; an all-zero alpha means opaque.
- An animated PNG shows its default image only.
- The `png` crate's memory limit is best effort: its raw-row buffers are not counted. They are bounded by the counted row, and the job object caps the whole process.
- Image bytes and pixels are not wiped, as in `kx-ipc`: the worker runs as the user, who can read their own memory anyway.
- The worker keeps the user's SID and logon session, so at Medium it could still read the user's own files, the history folder among them. ADR-0004 asks for less privilege, not a sandbox; an AppContainer or a separate low-rights account is a later hardening item (`docs/items/P14.md`).
- No `cargo fuzz` target: property tests stand in until the owner allows the nightly toolchain, as in `kx-kernel.md`.
- A compromised worker could hand back any DIB within the cap for an insert. The target app reads it as it reads any app's copy, and the keyboard never parses it.
- A DIB ask can wait behind a thumbnail or preview draw and miss `media_ms`; the insert then sets the PNG alone, which most apps read.
- **The stdin reader (P9):** the worker reads with `io::stdin().lock()`, whose std buffer keeps the last raw frame, a password included, until the next frame overwrites it. A short-lived worker holds it until its idle stop, `[vault] worker_idle_s`; the worker runs as the user, who can read that memory anyway.
- **`keepass` unwiped (P9):** the crate leaves a file's unprotected values and its XML in memory unwiped. Our copies are wiped, and the rest goes as the worker exits at its idle stop.
- **`age`'s and std's buffers (P9):** `age` 0.11.5's `StreamWriter` holds each plain chunk in a plain `Vec`, never wiped: the new secret key at padlock (`cipher.rs`, `lock`) and up to 64 KiB of notebook at seal. std's 1 KiB stdout buffer keeps the last small fields of an `Entries` reply; both go as the worker exits at its idle stop, and the worker runs as the user, who can read that memory anyway.
- **KeePass gzip and XML (P9):** neither has a cap of its own, so a file can expand far past `MAX_KEEPASS_BYTES`, but only after its own password opened it. `VAULT_MEMORY_MB` or a stack overflow then ends the worker, and the host answers `Failed`.
- **A compromised vault worker (P9):** it sees each password and notebook part the host hands it, and could keep them, as it still runs as the user with no sandbox (ADR-0004, `docs/items/P14.md`). The host checks every reply it reads (`kx-platform.md`), and the module reads each part as untrusted, so a false answer cannot break the keyboard.
- **Sound outside our buffers (P11):** WASAPI's and `cpal`'s own buffers, std's stdin buffer, which keeps the last hand-in frame, and std's 1 KiB stdout buffer, which keeps the last bytes of a `Sound` note, are not wiped. They go as the job ends at `idle_min`, and the worker runs as the user.
- **No memory figure from the worker (P11):** every `Done` says 0 MB, as the worker cannot read its own peak; the host stamps each one with its job object's peak (`kx-platform` `worker/stream/flow.rs`).
- **The engine's buffers (P11):** `transcribe.cpp` copies sound and text into buffers we cannot wipe. They go with the model or as the job ends, and the worker runs as the user.
- **The card part's own imports (P11):** `ggml-vulkan.dll` imports `vulkan-1.dll`, which Windows finds in System32 when a driver brings it; on a PC without Vulkan it looks on in the current folder and `PATH`. The Windows spawner's clean start closes that: the worker's own folder as working folder and a system-only `PATH` (`env.toml`). A planted file would still run only as this restricted worker.
- **A trickling server (P11 fetch):** a server that sends a byte within each `stall_s` can make a download slow, but never longer than the row's size, and Pause and Cancel are answered between its reads.
- **One request in flight (P11 fetch):** a Pause or Cancel that lands during a read waits for that read, at most `stall_s`, and one during an address's request waits for its name, connection, head and redirects, each at most `stall_s`, as the job runs on one thread.
- **Fingerprint of the stream (P11 fetch):** the SHA-256 covers the bytes as written, plus a resumed part read back at its start; the file's length on disk is checked and it is flushed before the rename. Another program of the user changing the part meanwhile is outside the model, as it runs as the same user.
- **A pre-created models folder (P11 task 29, below the bar):** another local user who makes the default models folder first keeps their own rights on it, as the host never changes a folder already there, so a file could change between its SHA-256 check and the worker's load. That needs a second account on the PC and a parser bug in the engine, which runs only here; the later fix is to refuse, or guard again, a models folder whose owner is not the user.
- **A name taken in a race (P11 fetch):** the job checks the name is free at the start and just before the rename, but a file another program of the user makes between that check and the rename is replaced, as the rename is Windows' own.
- **Links (P11 fetch):** a link or folder at the part's name is refused before it is opened, though a program of the user could swap one in between the check and the open; a hard link cannot be told from a file. Either needs the user's own rights over the folder.
- **A request already on the wire (P11 speech-net):** a Cancel stops a call before its head and between its 64 KiB body chunks (`SEND_CHUNK`), but a WinHTTP wait already begun (the connection, a chunk's write or the answer's head) runs to its end, within `net_wait_s`. Its outcome is never told, and the host has already ended the run.
- **Leftovers outside our buffers (P11 speech-net):** std's stdin buffer keeps the last raw frame, a key or a sound part included, and its 1 KiB stdout buffer the last bytes of a text note (`main.rs`). The boundary's SHA-256 leaves the sound's last block unwiped on the stack (`net/multipart.rs`), WinHTTP copies the head and body (`kx-platform-net.md`), and all go as the job ends with its run, as the worker runs as the user.
- **`serde_json`'s scratch (P11 speech-net):** the text is read straight into a wiped string, but an escaped string passes through `serde_json`'s own scratch buffer, which is not wiped. It goes as the job ends with its run, and the worker runs as the user.
- **Tidy F5 reads names only (P11 task 22):** an alias declared outside the job's folder (`use kx_platform_net as net;` in `main.rs`), a re-export through another module, a call into the other job's code, or a dependency renamed in `Cargo.toml` would get past it. The worker's `tests/root.rs` keeps each banned crate a dependency under its own name, the three jobs name each other nowhere today, and review covers the rest; a type-level split would need its own crates (ADR change).
