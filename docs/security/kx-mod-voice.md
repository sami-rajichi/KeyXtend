- **Owner:** product owner
- **Last review:** 2026-11-21 (P11 part 2 task 23 fix wave: Remove key on a sealed key's own row while its service or cloud services are off, a start that deletes the keys of rows no longer offered, never in a hidden run, and a refused removal shown with the key kept); 2026-11-20 (task 22: an older build's loss of the counts added under Accepted); 2026-11-20 (task 20b: a card's check reads the clip of the language in front, ADR-0052, and counts for that language alone). Older reviews are in git.
- **Status:** Reviewed
- **Scope:** `crates/kx-mod-voice`: the manifest, the `[voice]` settings, the models table (`models.toml`, `models`), the services table (`services.toml`, `services-own.toml`, `langs.toml`, `services`), the cloud rules (`cloud`), the cloud keys (`keys`), the typed lines (`line`), the device rule (`device`), the scorer (`score.toml`, `score`), the flow (`flow`), History, the counts and the store (`history`, `counts`, `store`), the models folder (`folder`), the downloads (`fetch`), Compare (`compare`), the panel's state (`panel`, `view`, `options.toml`), and the module and its actor (`module`, `actor`), which wire them to the ports and the bus. It runs inside the uiAccess `keyxtend` process; the speech jobs and downloads run in `keyxtend-worker` (ADR-0042).

## Capabilities
| Capability | Why needed | What breaks without it |
|---|---|---|
| `Voice` | An event gate (ADR-0042 decision 8): the key, its light, the bar's view, its clicks and the text to type, and the panel's line, its keys and its close (ADR-0049). | The module cannot show the bar or hand text to the keyboard. |
| `Microphone` | It gates `SpeechKey`, which records and transcribes in the worker. | The module does not start (`every_service_it_needs_is_gated_by_a_capability_it_holds`). |
| `Network` | It gates `ModelFilesKey`, for the model downloads the user asks for, and `CloudSpeechKey`, for the services the user switched on (ADR-0047 decision 11); the manifest requires the cloud port, which the app provides in a normal and a hidden run (task 12). | The module does not start; no model can be downloaded and nothing is sent. |
| `SecretStore` | It gates `VoiceShelfKey`, the store's own shelf over `<data>/voice/` with its own key: the history, kept recordings, counts, card checks, compare numbers and the cloud keys (`keys/<service id>`). | The module does not start. |
| `ReadFocusedText` | It gates `FieldWatchKey`, so a password box shows dots, no Copy, and keeps nothing. | The module does not start. |
| `WriteClipboard` | It gates `ClipboardWriterKey`, for Copy on the bar and a history row, and `PasteText` and `TextPasted`, for Paste at once. It never reads the clipboard: the clipboard history keeps and puts it back. | The module does not start. |
| `OpenFolder` | It gates `FolderRevealKey`, which shows the models folder in the file manager: a plain folder only, never a file or a link (ADR-0046). The actor checks the path (`FolderPath::new`) and calls it in a job. | The module does not start. |
| `OpenLink` | It gates `WebLinkKey`, which the manifest requires and the app provides: a card's facts page or the page where keys are made, each the row's own HTTPS address from the compiled-in table, never a typed one (edge 23); opened in a job (`link_on_a_cards_facts_reaches_the_browser_through_the_modules_own_lookup`). | The kernel does not start the module when no one provides it (`Reason::Missing`); a host that refuses the lookup still starts it, and links then log their refusal by kind while the rest works. |
| `ReadClipboard` | It gates `ClipTake` and `ClipTaken`: the key page's Paste asks the clipboard history for its text, as Quick-fill does, which forgets that copy; the text goes straight into a `Secret` and is sealed as the key. The relay takes only an answer naming this module, so a vault Paste of the same round is never sealed (`another_modules_answer_of_the_same_round_is_never_sealed_and_its_own_is`), and one not answered within `take_ms` (its floor past the clipboard's longest read, as the vault's) shows the busy note and its late answer is dropped. | The module does not start (its relay is refused). |

- It has no `InjectInput` (`it_holds_the_plans_capabilities_and_never_injects_input`): the keyboard stays the only typist.
- `SessionWatchKey` and `CalendarKey` are ungated, as they carry no content (ADR-0042 decision 9).
- Every service comes through `ModuleCx::service`, so the manifest's gates hold; the events it hears from others (`Typed`, `PointerPressed`, `PressesWanted`, `PressesAsk`, `LayoutChanged`, `LayoutAsk`, `ClipTaken`) need only gates it holds (`the_events_it_hears_from_others_need_only_gates_it_holds`).

## Threads and what each holds
| Thread | Runs | Holds | Waits on |
|---|---|---|---|
| The kernel's, at start and stop | `[voice]`, the services, the watches, the relays; the stop sends Quit and joins the actor | Nothing after the start | The actor only, which waits on no job or text |
| `kx-voice`, the actor | The flow, the panel, the store, Copy, the folder's scan, make and remove, the downloads' start and buttons | The text on the bar and its pieces (`Secret`), History (`Secret`), the facts, the runs between calls | Its inbox, up to the flow's next deadline; Copy up to `copy_ms`; the disk for the scan, the shelf and settings writes |
| `kx-voice-job`, one per job, never joined | A run's open and each call (one at a time per run, in order), the devices, a file's fingerprint (one at a time, each file once while queued or read) and facts, a card's check, the folder reveal; a cloud upload's key read and `send` (`actor/ask.rs`), for a dictation (`actor/net.rs`) or each of Compare's cloud models (`actor/trial.rs`); a key's test with its key read there, and a card's link (`actor/keyed.rs`) | The run while it calls; a kept recording or a cloud dictation's speech (`SecretBytes`) until it reaches the inbox or `send`; the cloud key (`Secret`) from its read until `send` takes it | The worker, within the port's own waits; the shelf for the key |
| `kx-voice-type`, the typer, never joined | Publishes each `TextAsk` in order, so one text is in flight; the keyboard types it on this thread. Texts still queued when the actor lets it go are never typed | The text being typed (`Secret`) | The keyboard, for the whole text |

- Every tell (a run's notes, a download's notes, the watches, the bus's relays) only posts to the inbox. A relayed key or click outside our windows carries no text: `Typed` and `PointerPressed` arrive as `Elsewhere`.
- A job's port panic counts as `Internal` and is told as a fault, even when the run panics again as it closes (`a_port_that_panics_in_a_call_tells_a_fault_and_frees_the_run`). A panic on the actor hides the bar, darkens the key, lets presses go and raises `MODULE_FAILED`; its runs close as it unwinds (`a_panic_on_the_actors_thread_hides_the_bar_closes_the_microphone_and_tells_the_user`).
- At the stop the watches go first, the flow closes every run, a failed save (History, counts, checks or scores) is tried once more, downloads pause (their parts stay) and the runs left close as they drop. A run out in a job closes when the job ends; the stop never waits for it or for the typer (`a_text_goes_out_on_the_typers_thread_and_a_held_keyboard_never_holds_the_stop`).
- With `on` off the module asks for no service, starts no thread, shows no bar and lights no key (edge 36, `with_the_feature_off_no_bar_shows_no_key_lights_and_nothing_starts`).
- Logs carry fixed texts, error kinds, a box's kind and a typed count only, never a text, a recording, a file name or a folder (`a_failed_copy_save_reveal_or_run_logs_no_text_or_folder`); a settings write is logged by `WriteError::kind`. Two debug lines hold kinds and numbers only: why a dictation runs on the processor although a card is picked, and how a card's check ended, with the words apart as a number, never the texts (`device::told`, `actor::tests::logs::cards`).

## Threats (STRIDE-lite)
- **Spoofing:** a renamed copy of a model is known by its fingerprint (`Table::printed`), not its name. A card's verdict attaches only to a fingerprint read from the file, never to a file served by its name and size.
- **Tampering:** every address is HTTPS, on a host listed by name (`link_named`, the port's own rule; a redirect may also reach the hosts under a listed `.` domain, which the table's test pins to `.hf.co`), pinned to a 40-hex commit, and ends in the row's file; every row carries a 64-hex SHA-256 and its size. A table that breaks any rule turns local models off and never panics. A download asks only for a row's own address, host list, size and SHA-256 (`Row::fetch`), and the worker checks the file before it is used; a wrong size or fingerprint deletes the part and tells the Print note. A download never replaces a file holding the row's name; that file must be deleted first. The shelf seals each blob (ADR-0010); the store refuses another mark, a newer version and a text whose id differs from its name.
- **Logging / repudiation:** the scorer and the check hold texts in `Zeroizing` or `Redacted`; no text reaches a log or an error.
- **Information disclosure:** the scorer keeps no text, and a check keeps only its verdict and timings. A hidden run, a password box and `history` off keep nothing (`Rules::of`; the flow sends no keep from a password box or a hidden run, and never asks for the sound with `history` off, so it stays in the worker); `Debug` of the store, History and the codec shows no text or sound, and nothing is logged. Compare keeps numbers only; its texts are `Secret` and wiped after scoring. The microphone never records unseen: Compare's recording shows the Listening bar and lights the key, as a dictation does.
- **Denial of service:** the actor never waits on the worker or the keyboard: runs, reads and checks run in jobs, texts on the typer, and the stop joins only the actor. A run takes one call at a time, in order, so a slow worker queues calls instead of racing them. The tables are read once at first use; a bad settings value resets alone, and a bad pick goes without the other languages' picks. Automatic never picks a card that has not passed its check or lacks room, and says why it uses the processor. One card check runs at a time and none starts during a dictation or Compare; a check held back runs once when they end, and a faulted one waits for the next layout, devices read, `[voice]` change or folder read, so nothing loops (`src/actor/tests/cards.rs`). The store's limits come from `[voice]` and `MAX_BLOB_BYTES`; a failed write waits for the next change instead of looping.

### Accepted (with reason)

- At the stop or a panic, a run busy in a job closes only when its call returns, so an opening microphone can stay on up to `ask_ms` after the light goes off. A fresh job's start may take up to `load_s`, though its microphone opens only at the end of that start and shuts at the Close queued behind it.

- With no keyboard, the typer's round map keeps a few bytes per text until the stop.
