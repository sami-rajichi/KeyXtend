# Security note: kx-ipc

- **Owner:** product owner
- **Last review:** 2026-11-20 (P11 part 2 task 22: the net asks row names `MAX_SPEECH_PIECES` and a send of about 7.5 KB, from task 9's review); 2026-11-19 (P11 part 2 task 19b: AssemblyAI's shape as code 5, carrying only its model header's name, a token read strictly, ADR-0051; fix round 1: `rules::unset_header` refuses a model header naming the key's header or one a request sends (the user agent too, fix round 2), and `rules::AUTHORIZATION` and `CONTENT_TYPE` are held there once); 2026-11-19 (P11 part 2 task 16h: the Azure shape removed, its code 2 refused as unknown, ADR-0050); 2026-11-17 (P11 part 2 task 7: the `speech-net` frames, their caps, wiped keys and sound, and the cloud request rules the port now shares); 2026-11-16 (P11 task 29 `kx-security-check`: the host-list rules `listed`, `covers` and `names`, where a `.` entry takes the hosts under a domain and a first address needs a plain entry by name; `listed`'s doc now says a two-name public suffix passes; final); 2026-11-14 (P11 task 9: the voice and fetch frames, their caps and wiped buffers); 2026-11-05 (P9 `kx-security-check`: frame caps against a crafted worker, nothing new; P9 Task 23: the vault frames, their caps and wiped buffers); 2026-10-31 (P8 security check: a dripped reply's buffer and the worker's command words; P8 task 6: the frame format and its limits; P8 final fix: the DIB ask and reply)
- **Status:** Reviewed
- **Scope:** `crates/kx-ipc`, a library with no module of its own. The worker host (P8 task 9) writes asks and reads replies; `keyxtend-worker media` (task 8) reads asks and writes replies (ADR-0004, ADR-0034 decision 5). It also holds the worker's command words and exit codes (`MEDIA_JOB`, `MAX_PIXELS_FLAG`, `CLEAN_EXIT`, `REFUSED_EXIT`), so the host and the worker read one copy, and the worker's memory figures (`READ_TIMES`, `DECODE_BYTES`) that the clipboard settings check reads through `kx-module-api`. From P9 it also holds the vault job's frames (`VaultAsk`, `VaultReply`), its job word and every box fact the host, the worker and the settings share (`limits.rs`, ADR-0038 decision 6). From P11 it holds the `voice` and `fetch` jobs' frames (`VoiceAsk`, `VoiceNote`, `FetchAsk`, `FetchNote`), their job words and the `[voice]` ranges the asks carry (ADR-0042, ADR-0043 decision 8). From P11 part 2 it holds the `speech-net` job's frames (`NetAsk`, `NetNote`), its job word `NET_JOB`, and the cloud rules and caps the `CloudSpeech` port checks with (`rules::https`, `token`, `form_value`, `key`, `piece_bytes`, `NET_*`; ADR-0036, ADR-0047).

## Capabilities
| Capability | Why needed | What breaks without it |
|---|---|---|
| None of its own | It reads and writes frames on the streams it is given and opens no pipe, file or socket. The `Pictures` port it serves needs no capability (ADR-0034 decision 3), and the `Boxes` port's `VaultData` gate is the kernel's to check (ADR-0039). | N/A |

## Data handled
| Data | Class (Secret/Sensitive/Public) | Stored where | Encrypted | Retention |
|---|---|---|---|---|
| Image bytes in a `Draw` or a `Dib` ask (copied by the user) | Sensitive | Memory, and the pipe between the host and its worker | No; only the two processes hold the pipe | Until the frame is dropped |
| Pixels in a `Pixels` reply, a DIB in a `Dib` reply | Sensitive | Memory, and the same pipe | No | Until the frame is dropped |
| Passwords, notebook parts and KeePass values in a vault frame (P9) | Secret | Memory as `Wiped`: lent, or kept in `Zeroizing`; `read_wiped` reads into a buffer wiped as it grows; and the same pipe | No | Until the frame is dropped |
| Padlocks, sealed boxes and KeePass files in a vault frame (P9) | Sensitive: already locked | Memory, unwiped, and the same pipe | `age` or KDBX | Until the frame is dropped |
| A piece's text and a card check's texts in a voice note (P11) | Secret | Memory as `Zeroizing<String>`, read into a buffer wiped as it grows; the same pipe | No | Until the frame is dropped |
| Sound pieces in a voice ask or note (P11), and a listen-only run's speech at Stop (P11 part 2): 16 kHz mono 16-bit | Secret | Memory as `Wiped`, at most `MAX_SOUND_BYTES` (1 MiB) a frame; the same pipe | No | Until the frame is dropped |
| Model, detector, clip and download paths (P11) | Sensitive: may name the user | Memory and the same pipe | No | Until the frame is dropped |
| Addresses, hosts, fingerprints, device names and language codes (P11) | Public | Memory and the same pipe | No | Until the frame is dropped |
| The user's cloud key in a net call (P11 part 2) | Secret | Memory as `Wiped`: lent by the host, kept in `Zeroizing` by the job, read into a buffer wiped as it grows; the same pipe | No | Until the frame is dropped |
| Sound parts in a net ask, and a piece's text in a net note (P11 part 2) | Secret | Memory as `Wiped` (at most `MAX_SOUND_BYTES` a part) and `Zeroizing<String>`; the same pipe | No | Until the frame is dropped |
| A service's address and model id in a net frame (P11 part 2) | Sensitive: a typed Custom address, or an Other model, is the user's | Memory and the same pipe | No | Until the frame is dropped |
| Form and header names, language codes and a row's limits (P11 part 2) | Public: the services table's | Memory and the same pipe | No | Until the frame is dropped |

`Debug` of `Ask` and `Reply` prints lengths, never bytes, and so does `Debug` of the vault frames, which never shows a value. `Debug` of the voice and fetch frames shows ids, codes, numbers, lengths, language, runner and card tags, and device names and drivers, never a text, a sound or a path. `Debug` of the net frames shows ids, the shape and its field names, the header's name, the language, the limits, counts and lengths, never a key, a sound, an address, a model or a text. Errors name only the kind of refusal.

## Inputs from outside (files, IPC, OS callbacks, clipboard, network)
| Input | Validation | Size/time limit | Fuzzed |
|---|---|---|---|
| Replies the host reads, from a worker that decodes hostile images and may be compromised | Magic, version, then the kind (`Pixels`, `Dib` or `Failed` only) and the length within that kind's range, all before any payload byte is read. Width and height from 1 to `MAX_SIDE`; the length must equal the fields plus width × height × 4 before the pixels are read; a DIB holds 1 to `MAX_IMAGE_BYTES` bytes and is never parsed here; the reason comes from a fixed list | `MAX_REPLY_LEN`: 8 + 4096 × 4096 × 4 bytes (64 MiB + 8). The buffer starts at `READ_CHUNK` (64 KiB) and doubles only as bytes arrive | Property tests (proptest): random bytes; a good header with any kind and length; a changed byte in a good frame; every cut |
| Asks the worker reads, from the host | The same header checks (`Draw`, `Dib` or `Bye` only). Codec from a fixed list, side from 1 to `MAX_SIDE`, a DIB's cap from 1 to `MAX_IMAGE_BYTES`, an image of at least one byte; `Bye` has id 0 and no payload | `MAX_ASK_LEN`: 5 + 64 MiB (`MAX_IMAGE_BYTES`, the largest entry `max_entry_mb` allows) | The same properties |
| Frames either side writes | The writer runs the same checks and refuses before writing a byte, so neither side sends what the other refuses | The same caps | Round-trip properties |
| Vault frames, read by each side (P9) | The media header with their own kinds, so a media reply is no vault reply. Every length, part, entry and field within its cap before its bytes are read; a password must be UTF-8; a part's name must be one `BOX_PARTS` names. A work factor must be within `MIN_BOX_WORK` to `MAX_BOX_WORK` | `MAX_BOX_BYTES` (64 MiB), `MAX_KEEPASS_BYTES` (16 MiB), `MAX_LOCKED_BYTES`, `MAX_RECIPIENT_BYTES`, `MAX_PASSWORD_BYTES`, `MAX_FIELD_BYTES`, `MAX_ENTRIES`, `MAX_FIELDS` | Property tests: round trips, random bytes, a changed byte, every cut (`tests/vault/props.rs`) |
| Voice notes the host reads, from a job that runs hostile model files (P11) | Their own kinds, each with its length range, checked before any payload byte. | Voice asks the job reads (P11) | Each setting within its `[voice]` range (`THREADS`, `PAD_MS`, `PIECE_S`, `RECORD_MAX_S`, `LEVEL_HZ`, `SILENCE_STOP_S`); language, runner and card id visible ASCII; paths without a NUL; sound in whole samples | `MAX_PATH_BYTES` (4096) a path; a hand-over at most `MAX_SOUND_PIECES` pieces | The same properties |
| Fetch frames, read by each side (P11) | Addresses start with `https://` and are visible ASCII; hosts are lower-case letters, digits, dots and hyphens; the path leaves room for `PART_EXT`; size from 1 to `MAX_MODEL_BYTES`; `stall_s` within `STALL_S`; progress at most its total, which is a size from 1 to `MAX_MODEL_BYTES` | `MAX_URLS`, `MAX_URL_BYTES`, `MAX_HOSTS`, `MAX_HOST_BYTES`, `MAX_MODEL_BYTES` (64 GiB) | Property tests (`tests/fetch/props.rs`) |
| Net asks the `speech-net` job reads (P11 part 2) | Their own kinds and lengths. Header and form field names, AssemblyAI's model header, a form's region code and the language pass `rules::token` (letters, digits, `-`, `_`), form values `rules::form_value` (visible ASCII and spaces), the key `rules::key` (visible ASCII), checked in its wiped buffer, and the model `rules::model` (a token's bytes and `.`, `/`, `:`, in `/` segments none empty, `.` or `..`). `ElevenLabs`, Gemini and AssemblyAI refuse a run with no model (`ShapeCode::needs_model`, which the port shares). Shape and header codes from fixed lists, so code 2, a dropped shape's (ADR-0050), is refused like any unknown code; `wait_s`, `tries` and each limit within `NET_WAIT_S`, `NET_TRIES`, `NET_MAX_MB`, `NET_MAX_S` (a piece at most 600 s, 19.2 MB raw), `NET_PER_MIN`, `NET_AT_ONCE`. Each piece's size is whole samples within `piece_bytes` of the row's limits, at most `MAX_RECORD_BYTES` together; a sound part is non-empty whole samples for a piece below `MAX_SPEECH_PIECES` | A send or test about 7.5 KB at most; at most `MAX_FIXED` fixed fields, `MAX_KEY_BYTES` a key, `MAX_SPEECH_PIECES` sizes, `MAX_SOUND_BYTES` a sound part | Property tests (`tests/net/props.rs`), including random payloads under a net header: whatever reads writes back the same, so it holds every rule |

| A service's whole reply, read by the job (task 8) | The crate holds its cap; the job enforces it and answers `Strange` past it | `MAX_NET_REPLY_BYTES` (4 MiB; ten minutes' words with their timings stay under 1 MiB) | The job's own reader tests |

The crate sets no time limit: the host's deadlines (`media_ms`, `vault_ms`) and kill on timeout belong to the worker host (task 9).

## Threats (STRIDE-lite)
- **Spoofing:** frames carry no authentication; the pipe is the boundary. The host hands only inherited anonymous pipe handles to its own child (ADR-0004), and the reply's `id` lets the host refuse an answer to another request (task 9).
- **Tampering:** a compromised worker can send any bytes, so every field is checked before use and a length that disagrees with its fields is `Inconsistent`. The host then checks the size it asked for (`Pixels::new`) or the DIB's length against its cap. Tests: `a_field_out_of_range_is_refused`, `pixels_that_are_not_width_by_height_are_inconsistent`, `a_changed_reply_never_panics_and_what_reads_writes_back_the_same`.
  - Request splitting (P11 part 2): the key, the address, the header and field names and the form values the job puts in a request hold no control character, so no CR or LF can add a header or a part (`a_name_or_value_that_could_break_a_request_is_refused_when_written`, `a_key_that_could_break_a_request_or_a_wait_out_of_range_is_refused_when_written`, `a_bad_call_or_run_is_refused_when_read`). The model and language hold no `"`, `\`, `?`, `#`, `%` or space, and a model no `.` or `..` segment, so neither breaks a JSON body or climbs an address's path (`a_model_or_language_that_could_break_a_body_or_an_address_is_refused_both_ways`).
- **Version confusion:** the magic `KXIP` and the version byte come first, so another version or stray output on the pipe is `BadMagic` or `BadVersion`. Each side reads only the other side's kinds (`BadKind`), so an echoed ask is never taken as a reply. Tests: `a_wrong_magic_is_refused`, `another_version_is_refused`, `an_unknown_kind_is_refused`, `each_side_reads_only_the_other_sides_kinds`, `each_side_reads_only_the_other_sides_dib_kind`.
  - Each job reads only its own kinds, so a `voice` job never takes a fetch or net ask, and the `speech-net` job never a voice ask (`every_kind_belongs_to_exactly_one_reader_and_the_codes_have_no_gap`, `each_voice_frame_is_refused_by_every_other_reader`, `each_fetch_frame_is_refused_by_every_other_reader`, `each_net_frame_is_refused_by_every_other_reader`).
- **Logging / repudiation:** the crate never logs. `Debug` shows lengths only (`debug_shows_lengths_never_content`, `debug_shows_the_dib_frames_lengths_never_content`, `debug_shows_no_text_sound_or_path`, `debug_shows_no_path_or_fingerprint`, `debug_shows_no_key_sound_address_model_or_text`), and `Why`, `VoiceFault`, `FetchFault` and `NetFault` are fixed enums, so a worker cannot push free text, or a service's words, into the host's logs. A device name with a line break or a right-to-left override is refused (`a_device_name_or_driver_with_a_hidden_format_mark_is_refused_both_ways`).
- **Information disclosure:** content stays in memory and in a pipe only the two processes hold. Media buffers are not wiped (Accepted); a vault frame's secrets are, in the crate's own buffers, and so are voice texts and sound, and the net frames' key, sound and texts.
- **Network reach (P11):** a fetch ask refuses an address that is not HTTPS before it is sent, and carries the only hosts a redirect may name; the fetch job enforces them on each redirect (task 13). A `.` entry takes the hosts under a domain of at least `UNDER_NAMES` names, never a bare top-level domain, and `names` takes only a plain entry, for a first address (`tests/fetch/hosts.rs`).
  - `listed` knows no public-suffix list, so a two-name suffix such as `.co.uk` passes; the models table's test pins its `.` entries to exactly `.hf.co`, so a new one needs a reviewed test change (`kx-mod-voice.md`).
  - A net call's address passes `rules::https`, so a user name (`user@host`), a fragment, a capital, a `.` entry, a bad port or a number host (`2130706433`, `0x7f.1`, `192.168.1.20`) cannot make it reach a look-alike host or an address WinHTTP reads as IPv4, and `https_host` names the only host its requests and redirects may reach (the job, task 8). The port's `HttpsUrl` is built with the same rule, so every address it holds passes the frames (`an_address_that_could_reach_another_host_or_break_a_request_is_refused`, `an_address_that_is_not_plain_https_is_refused_both_ways`, `a_host_whose_last_label_reads_as_a_number_is_refused`). A service on the user's own network is reached by its name, never its IPv4 address.
- **Denial of service:**
  - Oversized frames: the length is checked against its kind's cap right after the header, before any payload byte is read (`a_length_past_its_kind_is_refused_before_the_payload`, `a_good_header_is_never_read_past_its_frame_or_cap`, `a_length_past_the_largest_image_is_refused_right_after_the_header`).
  - A lying length within the cap costs only what arrives, and never more than the cap; a growing read holds at most `READ_TIMES` times its length (`a_read_buffer_grows_past_neither_its_length_nor_twice_what_arrived`, `a_lying_pixel_length_is_refused_before_the_pixels`).
  - A reader never reads past its frame, so a refused frame cannot swallow the next one (`*_round_trip_and_end_at_their_frame`).
  - The voice and fetch kinds have their own ranges, and a sound frame stays near 1 MiB (`a_good_voice_header_is_never_read_past_its_frame_or_cap`, `a_good_fetch_header_is_never_read_past_its_frame_or_cap`, `a_sound_frame_stays_small_beside_a_whole_recording`).
  - A cloud run's sound goes in parts of at most `MAX_SOUND_BYTES` after its send, never as one frame, a piece is at most `NET_MAX_S`' top (600 s, 19.2 MB raw) and its sizes total at most `MAX_RECORD_BYTES`, checked by the port too; a text past `MAX_NET_TEXT_BYTES` is refused before it is read (`an_oversized_reply_is_refused_both_ways`, `a_good_net_header_is_never_read_past_its_frame_or_cap`).
  - Random and cut input never panics (`random_bytes_never_panic`, `a_cut_frame_fails_cleanly`). A worker that stops mid-frame blocks the read until the host's deadline ends it (task 9).
- **Elevation:** `#![forbid(unsafe_code)]`, no dependency beyond `thiserror` and `zeroize`, and no media or box parsing. Decoding stays in the worker, which runs from a restricted token without uiAccess at Medium integrity (ADR-0034 decision 5, `kx-platform-windows.md`).

## Findings
### Must fix (blocks Definition of Done)
- None.
- Done (task 29 code review): `listed`'s doc said "never a whole top-level one" while a two-name public suffix passes; the doc now says what the rule guarantees, and `names` gives the port and the net layer one by-name rule for a first address.
### Should fix (tracked issue)
- Done (task 16): the settings stay inside these limits, `max_entry_mb` at most 64 and `preview_px` and `thumb_px` at most `MAX_SIDE`; the app's agree test pins both (`apps/keyxtend/tests/agree/clip.rs`).
### Accepted (with reason)
- The host may hold up to `MAX_REPLY_LEN` for one reply: a worker that declares a near-cap `Pixels` or `Dib` length and drips its bytes makes `read_tail` double the buffer (`grow`) to about 64 MiB. The host sends one ask at a time, which bounds it.
- No authentication or encryption on frames: the pipe is anonymous and inherited only by our child. A named pipe would need the checks in ARCHITECTURE.md's IPC section.
- Image bytes and pixels are not wiped on drop; the clipboard module holds the same content unwiped in `Redacted`.
- A vault frame's locked data (padlocks, sealed boxes, KeePass files) is not wiped either, as it opens only with its password. A reader over std's `stdin` keeps the last raw frame there until overwritten (`keyxtend-worker.md`).
- No rate limit in the crate: one draw at a time within the host's deadline bounds the rate ADR-0004 asks for (task 9).
- After any error the stream is out of step; the host restarts the worker with backoff, and the worker exits.
- No `cargo fuzz` target: property tests stand in until the owner allows the nightly toolchain, as in `kx-kernel.md`.
- A frame cannot see order: a sound index sent twice, or a piece's text past its run's end, is the host's and the job's to refuse (tasks 10 and 14). The index cap bounds a hand-over to `MAX_SOUND_PIECES` pieces either way.
- The host may hold up to `MAX_SOUND_BYTES` for one dripped sound piece, far below the media cap.
- A net frame cannot see order either: a sound part must name the first piece not yet full and fit what its send's size leaves, and a part for no run is out of step; the `speech-net` job refuses those and answers `Gone` (task 8). Nor can it bound a run's texts in all: the host (task 9) takes a text only for a known run, at the next untold index below that run's piece count, and drops the run once its texts pass `MAX_NET_RUN_TEXT_BYTES`, so a compromised job makes it hold that much, never `MAX_PIECES` times `MAX_NET_TEXT_BYTES`. The host may hold one dripped text of up to `MAX_NET_TEXT_BYTES`.
- `NetFault::Range` names no field, as a `&'static str` cannot cross the pipe: the job uses it when its shape refuses a value the frames let through, such as a `/` in a model id it puts in its address, and the host tells it as the port's `Range`.
