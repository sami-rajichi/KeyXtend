# P3 memory, part 2: no hidden marks, and slim keys

## Goal
- Bring the idle keyboard under the P3 budget: ≤ 100 MB private working set and ≤ 140 MB private commit in Native (ADR-0021, spec §10, gate G8).
- Nothing the user sees changes, in any theme.
- Based on the measured gap in `.superpowers/sdd/2026-09-29-phase-3-keyboard-core/mem-gap-report.md` and the research `docs/research/2026-10-10-window-memory.md` (#3, the key diet).

## Scope
- In:
  - text drawn by Qt carries no bidi isolation marks (U+2066–U+2069);
  - each key builds only the parts its kind shows;
  - icons are tinted without one shader effect each;
  - glows exist only while a key is lit;
  - a before and after picture check of every theme;
  - a memory measurement.
- Out:
  - drawing text another way (QtRendering): it softens small text;
  - fewer hidden pop-ups (under 1 MB);
  - the low-memory WARP mode (a P13 idea);
  - any change of look, motion, size or accessibility.

## Owner decisions (2026-10-10)
- Drop the marks. If any picture of any text, in EN, FR or AR, changes by one pixel, stop and switch to a tiny bundled font that draws the marks as nothing (a new decision).
- Slim the keys now, in P3, instead of in P13.
- The owner checks the before and after pictures side by side before anything ships.

## Design notes
- **Crates and files:**
  - `crates/kx-ui/src/i18n.rs` and `src/i18n/compose.rs` (the marks);
  - `crates/kx-ui/qml/KeyText.qml`, split into one part per key kind;
  - `Key.qml`, `Led.qml` and `Icon.qml`;
  - new C++ glue `crates/kx-ui/cpp/tint.h`, with its bridge in `src/bridges/`;
  - `qmltest/tst_pictures.qml` and new Quick tests.
- **Key parts by kind:** `CharLegends` (main, Shift and AltGr legends), `SpaceText`, `NamedFace` (icon and label) and `LangFace` (carousel, cycle or list).
  - The key makes only the part its kind needs, through a `Loader`, and swaps it when the kind or the language-key design changes.
  - Each part owns the animations it plays: the legend rise, and the carousel turn.
- **Icon tint:** an image provider, `TintIcons`, renders an icon file at the asked size and fills its ink with the tint.
  - `Icon.qml` asks it by URL: the name, the tint and the size.
  - Its URL scheme is one Rust constant, which reaches QML through `res`.
  - It reads only files inside the bundled icons folder.
- **Glows:** the lock glow (`Key.qml`) and the light's glow (`Led.qml`) are made while the key is lit, and kept until their fade-out ends.
  - The light itself is made only on keys whose cell can light, as the face says.
- **Settings, tokens, texts:** no new keys. Fluent's isolation flag goes off in one place.

## Tasks
1. **No hidden marks in drawn text.**
   - *Files:* `i18n.rs`, `i18n/compose.rs`, the Rust tests, `qmltest/fixtures/ui-*.js` (regenerated), and a new `qmltest/tst_marks.qml`.
   - *Test first:*
     - no text the hub gives QML holds U+2066–U+2069 (every key with placeables, in EN, FR and AR, and OS names that hold them);
     - in Quick, every space-bar text and every text with arguments draws the same pixels with the marks and without them.
   - *Implement:* turn Fluent's isolation off, and remove those four marks from OS names in `clean`.
   - *Verify:* `cargo test -p kx-ui`, then Quick with `QML_DISABLE_DISK_CACHE=1`. Expect 0 failures and no QWARN.
2. **Picture baseline for the key work.**
   - *Files:* `qmltest/tst_pictures.qml` and `crates/kx-ui/README.md`.
   - *Test first:* with `KX_PICTURES_BASE` set, the picture test fails on any pixel that differs from the saved baseline, and names the picture.
   - *Implement:*
     - add dark mode, high contrast, a lit lock key, a dim key and a pressed key to the states pictured, for all three themes;
     - save the baseline from the commit before task 3.
   - *Verify:* run it twice on the same commit; expect 0 differing pixels.
3. **Each key builds only its kind's part.**
   - *Files:* `KeyText.qml` (split), new `CharLegends.qml`, `SpaceText.qml`, `NamedFace.qml` and `LangFace.qml`, and a new `qmltest/tst_keyparts.qml`.
   - *Test first:*
     - a character key holds no icon, space text or language row;
     - each kind holds only its own part;
     - a key that changes kind or design shows the new part;
     - the legend rise and the carousel turn still play.
   - *Implement:* the split above. Each part keeps today's anchors, fonts and colours.
   - *Verify:* Quick passes, and the task 2 picture check shows 0 differing pixels.
4. **Icons tinted without an effect each.**
   - *Files:* `cpp/tint.h`, `src/bridges/tint.rs`, `Icon.qml`, the Rust and C++ glue tests, and the Quick tests.
   - *Test first:*
     - the provider fills ink pixels with the tint and keeps their alpha;
     - a name outside the icons folder, or a missing file, gives an empty image and one log line;
     - no `MultiEffect` or effect layer is left under any key.
   - *Implement:* `TintIcons`, registered on the engine before QML loads. `Icon.qml` becomes one `Image`, with `opacity` for the tint's alpha.
   - *Verify:* tests pass. Pictures: 0 differing pixels outside icons. Icon edges may differ by at most 1 step in any channel, and the owner sees those side by side.
5. **Glows only while lit.**
   - *Files:* `Key.qml`, `Led.qml`, and Quick tests.
   - *Test first:*
     - an unlit key has no glow item;
     - a key that lights gets one, and keeps it until its fade-out ends;
     - turning it on again during the fade works;
     - the recording pulse still runs;
     - keys that cannot light have no light item.
   - *Implement:* make the glows, and the light, on demand as above.
   - *Verify:* Quick passes, and pictures show 0 differing pixels.
6. **Measure and record.**
   - *Files:* `.superpowers/sdd/…/key-diet-report.md` (scratch), `docs/research/2026-10-10-window-memory.md` (a short "measured after" line), `docs/items/P13.md` (key diet: built in P3).
   - *Test first:* none; this is a measurement.
   - *Implement:*
     - measure idle Native, ET66 and Dolch with the gap report's method: a release staged copy, `uiAccess="false"`, its own instance, 3 runs each, median and range;
     - also measure 24 size changes, as in G8's churn.
   - *Verify:* Native ≤ 100 / 140 MB. ET66 and Dolch are reported, not gated.

## Edge cases (each maps to a test)
1. A Latin name inside Arabic text, with digits and brackets (for example "Arabic (102)"): same pixels with and without the marks.
2. An OS layout or language name that holds U+2066–U+2069 has them removed.
3. A key's kind changes while it is alive: the old part goes and the new part shows.
4. The language key switches between carousel, cycle and list at run time.
5. A theme switch, or a switch between light, dark and high contrast, re-tints every icon.
6. A dim key: the icon's alpha matches today's.
7. A display scale change re-renders icons at the new size, still sharp (G11).
8. An icon name with `..`, a slash or a drive letter is refused.
9. A lit key turns off: its glow fades fully before it is removed. Lit again mid-fade: no jump.
10. High contrast: no glow is made, as today.
11. Dolch's lights that show while off stay exactly where they are today.
12. A language change still plays the legend rise on character and space keys.
13. Arabic and mark legends keep their fonts and baselines.

## Security
- The image provider reads only files under the bundled icons folder. Path checks are tested, and nothing reaches the network.
- No typed text, clipboard content or names of other apps' windows are logged. Icon names are our own.
- `unsafe` appears only in `src/bridges/tint.rs`, each block with `// SAFETY:`. Run `kx-security-check` §2–3 on the diff.
