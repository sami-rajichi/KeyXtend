# kx-ui

The UI: the texts in English, French and Arabic, the `[ui]` settings, the `ui` module and the hub it shares with the app, and, with the `qt` feature (on by default), the QML module `KeyXtend.Ui` and its cxx-qt bridges (ADR-0013). It depends only on `kx-module-api`, `kx-platform` and `kx-theme`, plus Qt and Fluent.

## Build

The `qt` feature needs Qt 6.11.2: set `QMAKE` to its `qmake.exe` and put its `bin` first in `PATH` for the command. `build.rs` lists every QML file in one table (`QML`, the root first) and every bridge in `BRIDGES`, and hands the root's resource URL to the crate as `MAIN_QML`. Without the feature (`--no-default-features`) the texts, settings, hub and module still build and test, as the Linux checks need.

`cpp/` holds the C++ the bridges call where cxx-qt-lib has no binding; they include it as `kx-ui/cpp/…` through cxx-qt-build's crate include root, and `build.rs` rebuilds when it changes.

`build.rs` also adds Qt's versioned `QtGui` header folder (from `qmake -query`), for `rhi/qrhi.h`, and writes `kx-ui-build.h` under `OUT_DIR`, which defines `KX_UI_PROBES` only with debug assertions, for the test-only probes and triggers. `qtbuild.rs` holds the Qt pin check and that header's writer, which the Quick tests' plugin (`tools/kx-test-icons`) shares, so it also refuses an unpinned Qt and writes the header without probes.

With debug assertions and `KX_UI_CHURN` set, the app churns through its own buttons' calls (`Churn.qml`, which `App` loads, plan in `src/churn.rs`): rounds that each show a key's tip, open and close the language list in the List design (in another design the key would switch the layout, so it stays still), minimise to the bubble and back, and show every theme once; then Caps Lock changes shown with no key sent (`FaceAction::FlipCaps`), then size steps up and down. The log then says `the churn ended`, for a memory check. It saves the theme and the size it steps through, and near the largest size the size ends smaller than it started. Only debug builds hold `Churn.qml`.

It also compiles in, as Qt resources, the icons the theme tokens name and every font under `assets/fonts/` (ADR-0016), found through `kx_theme::assets`; a missing icon file stops the build. `ASSETS` hands QML the fonts' URLs and the icons' URL as JSON, and the app never reads them from disk. `serve_icons` registers the icon provider (`cpp/tint.h`) on each engine before it loads QML: it draws `image://kxicon/<rrggbb>/<name>.svg` from the compiled-in icons at the size Qt asks, its ink in that tint, and refuses any other name with one warning and a clear image. Each icon is a texture of its own, outside Qt's shared atlas, so an icon between whole pixels draws the same in every run, and `Icon` keeps no cache, so each step of a colour change goes when the next comes. `serve_shadows` puts the soft shadows' adopter (`cpp/shadows.h`) on each engine before it loads QML too: `Soft.qml`, the only `RectangularShadow`, hands it its default material, which Qt 6.11 never frees, so the material goes with its shadow. Only the shown theme's files go into Qt's font list: kx-theme's `font_files.toml` names each family's files, the hub's `FontBook` (`QtFontBook` in the app) loads them before each load of the QML and on each read of the look (`Hub::look_json`), so whatever button or wake changed the theme, QML picks its families from them, and a wake drops the last theme's files after, so no text asks Qt for a family it lacks; `fontsChanged` follows the look's signal, so `KbWindow` picks them again (ADR-0021).

It also embeds the sounds kx-theme's `sounds.toml` names: `kx_theme::assets::bundle` reads each file strictly, `build.rs` writes its samples under `OUT_DIR` and generates a table that includes them 2-byte aligned, with each event's clips and balance, the rate and the voices, and a missing or bad file stops the build with its name. `sounds` hands them out as the `Speaker` port's `Clip`s, each event's `Cue` (its clip ids in turn and a linear gain) and `voices`; without the `qt` feature the table is empty, and nothing reads audio at run time.

## Qt's start

The app calls `harden_qt` before Qt's app object exists. It clears with `qunsetenv` every name with a Qt prefix (`harden::QT_PREFIXES`, any case) in the C runtime's narrow copy of the environment, which Qt's byte reads use, and from the wide copy its text reads use; a name the code page narrows to a Qt one, such as a fullwidth `ＱＴ_`, goes too. It also turns off Qt Quick's shader cache on disk, and `qt_sees` and `qt_reads` tell whether Qt's narrow and wide reads still find a variable. Then the app calls `pin_adapter` with the lowest-power GPU that `kx_platform_windows::gpu` finds, which sets `ADAPTER_VAR` (`QT_D3D_ADAPTER_INDEX`), so the keyboard never wakes a big GPU. In the uiAccess build the app also passes its folder, so Qt loads plugins only from there, and calls `pin_imports` on the engine before loading: QML modules then come only from the compiled-in ones and the `qml` folder beside the app (`QML_DIR`).

Next, `pin_drawing` sets `QSG_RENDER_LOOP=basic` and `QSG_NO_DEPTH_BUFFER=1` (`harden::DRAW_VARS`), and `pin_timing` sets the frame timing and buffer pool from `[ui]`: `QT_D3D_MAX_FRAME_LATENCY`, `QT_D3D_NO_VBLANK_THREAD`, `QT_QPA_UPDATE_IDLE_TIME` and `QSG_RENDERER_BUFFER_POOL_LIMIT` (`harden::timing_vars`), and the swap interval every window asks for (`harden::swap_interval`); the app logs them. Then `Shell::open` makes one shared graphics device (`Device`) when `drawing_pinned` reads both back through Qt's byte read, which each window adopts before its first frame, then loads the theme's fonts and the root QML (ADR-0021). The device is made only on the thread of Qt's app object, and elsewhere nothing is made and the pin stays; `build.rs` refuses a Qt other than the workspace's `qt_version`, as the device glue uses `rhi/qrhi.h`. When a frame finds the device lost, or drawn off the GUI thread, or a window's scene graph cannot start (`sceneGraphError`, which a `Watch` handles so Qt does not end the app), Qt's loop ends and `Shell::rebuilt` reloads the QML over the same hub. It makes the new device on the adapter the `Pick` finds anew and never drops that pin. Each try counts against `[ui] device_rebuilds`; a failed try answers `After::Wait` and a timer ends Qt's loop again after `device_retry_ms`, so the GUI thread never sleeps. Past the tries, or after an off-thread frame, each window makes its own, but a window that still cannot draw ends the app with one error. An off-thread frame, or drawing variables that did not read back, turn sharing off for the run, so no rebuild makes a shared device then. It answers `After::Again`, `Wait`, `End` or `Failed`, so the app runs the loop again or ends, with a failure when the windows could not be made again. The hub keeps whether the keyboard showed, was closed or was minimised (`Mode`), so the new `App` leaves it so. When a settings or look wake changes the look QML reads, every shown window drops Qt's cached graphics once its next frame is out, or once it hid (`release_after_frame`, `cpp/release.h`), so look changes do not pile them up, and a wake that keeps the look drops nothing; once none waits, the hub gives the heaps' free pages back through the `Memory` port (`Hub::decommit`, ADR-0023), once for back-to-back changes. Debug builds can mark the device lost (`Shell::lose`), a frame off the GUI thread (`Shell::stray`) or a window failed (`Shell::fail_window`), and count which windows draw on which device (`drawing`), which have `sceneGraphError` connected (`wired`), how many windows dropped their cached graphics (`released`) and how many of them while hidden (`released_hidden`), how many wakes ran and asked for that (`wakes`), how many materials the soft shadows' adopter took (`adopted`) and Qt's font families (`font_families`), for the device test; release builds have none of these, so a release run of that test checks nothing.

## QML views

`qml/` holds the keyboard window and its parts, moved from the P1 test build with its look. `main.qml` makes one `Ui` and one `Keyboard` and hands them to `App`, which holds the keyboard window (`KbWindow`, its body `Plate`), the minimise bubble, the notice banner (`Notice`) and the tray menu (`TrayMenu`), each over a click-through shadow window (`Glow`), and draws the tray icon's picture (`TrayPicture`). The windows read `settingsJson`, `langJson`, `lookJson`, `boardJson` and `stateJson`, redraw from each action's `{board, state}` answer, read everything again on `settingsChanged`, and only the texts on `textsChanged`.

- **Banner:** notices queue; one shows above the keyboard (or at the bottom of the main screen while it is away) with Try again when the app can restart what failed, and OK, and says how many more wait. A new keyboard language tells the queued notices again (`shownNotices`), and a banner made again after a device loss starts from them.
- **Tray (ADR-0019):** × hides the keyboard; a click on the tray icon opens the themed menu (Show keyboard, Quit) above it, in the system's language (`trayText`, ADR-0020). It closes on a pick, a second click on the icon, a press on any of our windows (`PressWatch` hears it without taking it), and another program's window coming to the front once `[ui] tray_grace_ms` has passed since it opened. The picture is the theme's badge, drawn again when the look or the settings change, or its window's scale; a taskbar on another screen is not followed (`docs/items/P14.md`). The icon goes before the UI ends.
- **Keys:** each key's face (`KeyText`) makes only the part its kind shows, `CharLegends`, `SpaceText`, `NamedFace` or `LangFace`, and makes the new part when the kind or the language key's design changes. Each part plays its own motion: the legend rise (`Rise`) and the carousel turn. A lock glow, a light (`Led`) and its glow exist only while they show, and ease on the key (`lockLit`, `ledLit`, `ledColour`), so one made mid-fade starts where the key is. `NamedFace` makes only its icon or its label, and each shadow layer (`Shade`) only the box or the shadow it draws; `tst_budget` fails any key kind that makes more items than today.
- **Language key:** Carousel, Cycle (`LangCycle`: globe, name, one dot per layout, the current one larger) or List (name and chevron). The List opens `LangList` (with its shadow in `LangPanel`): one page of `[ui] page_rows` rows (`LangRow`) above the keyboard with its left edge at the language key, driven by the board's arrows, Enter and Esc, with a pager when there is more than one page; which page shows, and whether its buttons turn, comes from the face's `page`.
- **Top bar:** the theme button cycles the themes (`bar.theme`). The lit size letter is plain text with a ring-coloured pill under it (`[bar] mark_px`).

- **Pointer overlay (spec §5.3):** `App`'s `AssistRead` reads `assistJson` once after `assistChanged`, on the event loop's next pass (`Qt.callLater`, never a frame), or after the rest of `[ui] poll_ms` when it read less than that ago, so streaming changes read at most once per `poll_ms` and nothing runs while no wake waits. It stays outside the overlay's `Loader`, which makes `Overlay` only while the hub names a `mode` or the pad's `scroll` part. Its one click-through window keeps one size for its life, as a resize stalls Qt's frames for up to a second: the ring's box and the widest badge (the mode's icon and Grab's word, the dot, the arrow and the wider speed word) with its `badge_margin`, on either side of the pointer, for the pointer anywhere inside the ring's box, as a hold keeps it within its still radius. A read only moves it, centred on what shows; when the pointer races away from a burst it keeps the badge whole and cuts the burst at its edge. Only the pointer's size, the theme, a font load or the display scale change its size. The badge's word follows the keyboard's language, and its room only grows, on the next pass from the word as set, so a narrower word, or one half set in the last language's font, never resizes it.
- **Hold ring:** `HoldRing`, from the P1 test build, waves once per `ring.seq` and bursts once per `burst.seq`; it hides at once when the ring clears, and reduced motion skips the burst. Each call shows its next part before it hides the last, so the window never hides and shows again in between.
- **Mode badge:** `Badge` shows the side key's icon for the hub's `mode` on a `badge_bg` pill with its own `badge_shadow`, with "Holding" while Grab carries, and while the pad scrolls its arrow and "slow" or "fast" (`badge.slow`, `badge.fast`), after a faded dot (`[badge] sep_px`, `sep_share`) beside a mode. Readers hear the mode or the arrow, then the rest, joined by the language's comma (`badge.join`); in Arabic only the words read right to left. It sits beside the pointer, its offset grown with a pointer bigger than Windows' default, and flips near the work area's right or bottom edge at the base offset, staying inside it.
- **Badge over our windows:** the badge fades out over our shown windows (the keyboard cut to its plate and corner, the bubble, banner, tray menu and language list). Once shown, the overlay joins a quiet guard run (`KbWindow.guardQuiet`), which keeps a shown tip and the pop-up the run puts in front, as the overlay draws nothing over our windows.
- **Scroll pad (spec §5.2):** `DPad` puts each arrow `[dpad] reach` of the way across the ring of arrows, from the hub's edge to the pad's, so 0.5 centres it as the iPod click wheel's labels. `Stop` pops in while the state names a `dir`, with one dot per speed under its square (`dot_px`, `dot_gap_px`, unlit at `dot_off`, in high contrast too, as Cycle's dots), and takes only taps on its disc, so the arrows keep their inner corners. A pressed arrow takes the keys' `press` shade and, in high contrast, `press_ink`. A tap sends `Keyboard.pad` (an arrow's id, or empty for Stop), which sounds like a key, and the pointer coming onto the disc or leaving it, or the window hiding or the pad going with it there, sends `padHover` once per change; a `HoverHandler` watches the whole disc, so gaps and the hub tell nothing. Readers and voice control find each arrow by an upright box centred on its icon, as deep as the room from the hub's edge or to the pad's and as wide as the boxes beside it allow, because Qt reports a turned item's box upright, and every turned arrow's would be the whole pad's. A dimmed pad, while the scroll module is off, takes no tap and tips why.
- **Scroll outline:** `App`'s `Outline` reads `scrollJson` on the event loop's next pass after each `scrollChanged` and makes four `Edge` windows only while the hub names a box: thin click-through windows titled `window.outline`, owned by none, inside the box, or just outside it when the box is ours (`ours`, our opaque list, which lies over them), in the ring colour (`hover_line` in high contrast), `[outline] px` wide, which fade in with `moves.outline`. The box is cut to the screen holding most of it, and one wholly off-screen draws nothing. A new box fades the edges that move out with `moves.outline`, moves them while unseen, as a resize stalls Qt's frames, and fades them back in; a box with the same values moves nothing, and reduced motion moves them at once. Each new set joins a quiet guard run and lies just under the keyboard (`Ui.layUnder`), and again when the keyboard shows again. While the hub's scroll state is live, the keyboard window asks `Ui.watchEntries` at each guard try after it shows until it takes, or at once when no guard run is pending, and calls `Ui.unwatchEntries` as soon as the module stops, which forgets the kept point.
- **Display scale (G11):** each window's size, and the keyboard's and its shadows' place, go through `Rescale`, which sets them again on a new scale or after Qt changed them, as Qt leaves the native window as it was. On a new scale, a new screen size, or when a screen comes or goes, the keyboard cuts itself again, asks to be placed again where it is in pixels, and takes the place it gets in the new Qt units (`Placing`); during a move or resize, that placement waits until it ends. A window made again after a device loss first goes where the keyboard keeps it (`st.at`), so its first report moves nothing. A new scale puts the shown bubble, banner and list back in place, the bubble from the keyboard's new place, and closes the tray menu.
- **Shadows:** a `Glow` window sits in whole Qt units around its box, so the shadow's edges meet its window's. The keyboard's shadow draws nothing while a live resize runs: each window draws on its own, so it would trail one or two frames behind.
- Every window is a no-focus tool window (ADR-0013); once shown, it is cut to its plate and corner, then guarded until the guard is done. A banner or tray menu names itself to the guard run (`Guard.qml`, which reads its title at each `Keyboard.guard(top)` try), so it lands in front where it shows again, even after a language switch.
- The keyboard and the bubble each own their tip (`Tip`), so Windows keeps it above them when the guard lifts them. A shown tip also lifts itself alone in front of our windows (`Keyboard.liftAlone`, by its title `window.tip`), hides as a guard run starts, and stays on the screen under its button.
- Names, labels and tips are translation keys, looked up in the keyboard's language: the layout's in front, unless `[ui] language` pins one (ADR-0020). Arabic flips text only; nothing mirrors, and a tip closes when the texts or the look change, so it never shows the last language.
- Keys that come in a later version are dimmed, never press, and tell readers and the tooltip "Coming in a later version". Right-click and Grab never press either while their state dims them (`dim`), as while mouse assist is off, and say so in their tip.
- **Controls act on the press they got (ADR-0024):** through `Act`, every key acts the moment the pointer goes down, and every other control (top bar, chips, resize corner, a move's second click, list rows and pages, tray menu, notice buttons, bubble, D-pad) at let-go, wherever the release lands. A slip onto a neighbour, into a gap or off the window never cancels a press, nothing it slips onto acts, and Qt's cancel acts on nothing. A move's or resize's end and a notice's buttons ignore the second click of a double click. The language key takes its part from where it was pressed.
- **Key repeat (spec §4.6):** a key the board marks `repeat` sends `Keyboard.press`, which types it, instead of a click, and `letGo` when the pointer comes up, wherever it is; Qt's cancel sends `leave`. While the language list is open, a key that drives it drives it at the press and never holds. One timer (`Hold`) runs only while the keyboard holds such a key (`holding` in the press's and each tick's answer) and shows with no list open, waits `repeat_delay_ms`, then calls `tick` every `repeat_every_ms`; the state is read again only when it changed. Hiding or the list showing ends the hold, and a failed repeat logs one warning, with no key.
- Text uses `Label` (grayscale, no ClearType fringes, plain text only; the texts test fails on any text element that could read markup), and hover uses `Hover` (the theme's tint, and a `Highlight` outline in high contrast). `Icon` is one `Image` the icon provider draws in its tint, with the tint's alpha as its opacity, so no icon needs an effect.

## Qt Quick tests

`qmltest/` checks the views over stand-ins for `Ui` and `Keyboard` (`FakeUi`, `FakeKeyboard`), because `qmltestrunner` cannot load a module linked into a Rust binary; `tst_app` builds `App` over them as `main.qml` does. They answer from `qmltest/fixtures/` (written by the texts test from the hub and the face's golden files) and from kx-theme's look fixtures, so QML never reads a stale value. The same test lays out the bundled fonts and icons in `target/tmp/qmltest-assets` as the app holds them, with the icon plugin (`tools/kx-test-icons`) that `qmltest/qmldir` loads, so every test's engine draws icons through the app's provider and serves the soft shadows' adopter, without which a test fails on the warning; run `cargo test -p kx-ui --test texts` first. Then run them with Qt's `bin` in `PATH` and `QML_DISABLE_DISK_CACHE=1`: `qmltestrunner -input crates/kx-ui/qmltest`. Any warning fails a test. CI runs them at 100 % display scale, so on a scaled display run them a second time with `QT_ENABLE_HIGHDPI_SCALING=0`. Tests that hover pass their windows to `pointer.js`, so the real pointer goes through them and a hand on the mouse cannot move a hover. The scale and place tests share their keyboard window helpers in `kbwin.js`. `board.js` holds the one item search, which `kbwin.js` uses too, and the keys' fonts, texts and bundled font loading that `tst_corners`, `tst_order`, `tst_pictures` and `tst_lang` share. A test that needs a font Windows ships asks `fonts.js`, which skips it by name on a system without that font, such as a CI image; a missing bundled font still fails. Texts carry no bidi marks (ADR-0022), so `tst_order` checks their reading order: a twin of the drawn text with one part as a link shows, through `linkAt`, where Qt lays that part out.

To see the board before an install, set `KX_PICTURES` to a folder (relative to the repo root, such as `target/pictures`) when you run the texts test; `tst_pictures` then saves each theme's board, light and dark, and Native's high contrast, as PNGs there: English, French and Arabic plain, Arabic with Shift and with AltGr, English with Caps Lock lit and with a key pressed, the dim keys in each. Set `KX_PICTURES_BASE` to a folder of such pictures instead, and the test fails naming each picture that differs and by how many pixels. Make and compare a baseline on the same PC and display scale, as the pictures hold device pixels. With neither set, it skips.

## The `[ui]` settings

`defaults.toml` holds the values and `settings.rs` the limits of each number. `language = "auto"` follows the keyboard's language, and `en`, `fr` or `ar` pins it; the tray always follows Windows. The check refuses an unknown theme, a language that is neither `auto` nor in `LANGS`, a `min_contrast` outside `kx_theme::contrast::MIN_CONTRAST` (never below WCAG AA), and a timing, row count or volume outside its range. `tray_grace_ms` may be 0, which turns the tray menu's grace off. `send_tries` and `send_wait_ms` set how a second copy hands Show or Quit to the running one; it reads the user's `[ui]` section without changing the file, and falls back to the defaults on any fault. `device_rebuilds` (0 to 10) caps how often one run tries to bring the windows back on a new graphics device after the device is lost or a window cannot draw; 0 goes straight to each window's own device. `device_retry_ms` (0 to 5000) is the wait before trying again when a new device could not be made yet, as a driver resets; Qt's loop runs meanwhile. Four frame timing knobs are read at start, and the first three default to what Qt does alone: `frame_latency` (0 to 3, Qt's 2) is how many frames Qt lets queue before it waits at a frame's start, and 0 drops that wait, though Direct3D's own queue may still hold a Present; `vblank_updates` off starts frames on Qt's update timer instead of the screen's refresh; `update_idle_ms` (0 to 50, Qt's 5) is that timer; `present_vsync` off shows each frame at once instead of at a refresh, though DWM still composes it at its refresh, and frames then go unseen, so it stays on (ADR-0026). They exist to tune the key light (G8), not for users. `buffer_pool_bytes` (0 to 8 MiB, read at start) caps the freed vertex buffers, and as many index buffers, that each window's renderer keeps to reuse (`QSG_RENDERER_BUFFER_POOL_LIMIT`); it keeps none by default, as Qt's own 2 MiB of each, with the graphics driver's pool, grew commit by 11 to 13 MB after use in a harness (ADR-0028). `press_frame` sets when a pressed key acts against the frame that shows it pressed (`PressFrame.qml`): `now` (the default, ADR-0025) draws that frame at once (`Keyboard.drawNow`), then types; `after` types at once and the press shows in the next frame; `first` types once that frame is out, or after `press_frame_ms` (1 to 1000); `drawNow` refuses while that window is mid-frame, which a frame mark it adds to the window tells. A let-go or Qt's cancel lets a waiting press act first, and a press waiting as the keyboard hides never acts. `frame_log`, read at start, has the app run a `FrameLog` when drawing is pinned to the GUI thread, and else say once that it stays off: each frame of our windows logs a `frame timed` line (its polish, frame start wait, render and present times, its whole time on the GUI thread with waits and Present, and that time without the start wait, `work_us`), and each press a `press timed` line, all in µs from when Qt got the press's message: the press reaching the window, the key's action starting, the key sent, the action and its redraw ending, then the steps of the first presented frame after it. `cpp/framelog.h` times these on the performance counter, the clock kx-gates and PresentMon use (`at_us`), and `frames::Log` joins them; no line holds a key, a position or text. `sound_key`, `sound_rclick`, `sound_pick` and `sound_drop` switch each sound, all on. `sound_volume` (0 to 100) scales every sound's gain linearly under the Windows volume, and 0 plays nothing; `sound_idle_ms` (1000 to 60000) is how long the speaker stays ready after the last sound, and its floor is twice the sum of the longest sound `sounds.toml` allows and about 100 ms of device latency.

## The hub

The app makes one `Hub` over its UI ports before any window exists, so it can note the user's focus, and gets a `Receiver<Request>` with it.

- **Bridges:** `install(hub)` hands it to the QML objects once, before QML loads, since QML makes them without arguments (ADR-0018). An object made before it warns and does nothing.
- **The `ui` module:** `UiModule` needs the keyboard face; its start hands the hub the checked settings, the face and its settings handle, and its stop lets the face go.
- **Texts (ADR-0020):** two sets. The keyboard's follow the layout the face shows (`KeyboardFace::lang`): after an action whose state changed, a new language switches them and sends `Wake::Texts`. A layout language without texts gets English, and so does the time before a layout names one. The system's texts (`tray_i18n`) speak `SystemLook::ui_language`.
- **Sounds:** `Hub::new` builds each event's cue once and hands the `Speaker` every clip; a new `sound_idle_ms` hands them again. A tap or a key's first press (`sent`) plays the key's next take after the frame log's mark, and a hold that fires, a pick-up and a drop play theirs from the bus's `AssistNote`s; a repeat, the top bar and the language list play nothing, and no play blocks or logs.
- **Pointer overlay:** `listen(&bus)` also keeps the mouse modes (`AssistChanged`), the scroll pad's way (`ScrollChanged`), the pointer while either shows (`PointerMoved`) and the hold's ring and burst (`AssistNote`) for `assist_json`. Its view names the `mode` shown (`grab` before `rclick`, null while the module is not live or every mode is off) and the badge's `scroll` part (`{dir, fast}` while the pad scrolls and the mouse module, which sends the moves, runs; else null), and adds the pointer size, Windows' default size (`pointerBase`) and the work area nearest the point (`area`, from the `Screens` port at each read).
- **Overlay changes:** a ring's `waveMs` is its hold time less `afterMs`; with no mode shown the ring and burst go, and with no mode and no scroll part the point goes too; no point is logged. A change sends `Wake::Assist` unless one waits for QML's read, so a run of moves costs one wake per read, and a new waker gets one QML never read.
- **Scroll pad:** `listen(&bus)` keeps the scroll module's state and the box to outline (`ScrollAimed`, physical pixels, and whether it is ours) for `scroll_json`, `{live, dir, fast, area, ours}`, then publishes `ScrollAsk` once so any start order works. A module that is not live shows still, slow and with no box, so a stop leaves no outline. A change sends `Wake::Scroll` unless one waits for QML's read, and a new waker gets one QML never read; no box is logged. Hiding the keyboard mid-glide (`keep_mode` from shown to away or minimised) hands the face one Stop, as Stop goes off the screen with it.
- **Page turns:** a `ScrollPage` sends `Wake::Page`, and the `Ui` object calls `turn_page` on the Qt thread. It reads the open list from the face's state at `[ui] page_rows` and sends the list's own page-button key (`page_back` or `page_on`) as `panel_key`, only where the list's `page` says it turns that way, and nothing with no list open; a turned page sends `Wake::Keys`.
- **Scroll guard calls:** `watch_entries(title)` keeps the pointer's last point outside the keyboard window at each entry, for the scroll target, and `lay_under(title, under)` puts an outline window just under the keyboard; `mark_pages(title)` marks the open list as a window that pages: while it shows, a pad tap turns its page whatever point was kept, and the list asks as it opens and at each guard try until it holds. Each is false while a window is not shown, and warns only when refused. `watch_entries` is also false, quietly, while the guard does not hold the keyboard yet; it warns once only when a guard run ends with the scroll module live and the watch never held. `unwatch_entries(title)` stops the watch and forgets the point; `watch_entries` is false while the scroll module is not live.
- **Keys wake:** while a face is attached, each `AssistChanged`, `LatchesUsed` and `ScrollChanged` sends `Wake::Keys` and the keyboard window reads its state at once, so the pad lights without waiting for the next relabel. `attach` subscribes those handlers on the bus `listen` kept, after the face's own, since the kernel always starts or restarts the `ui` module after the keyboard, and `detach` drops them.
- **Notices:** `listen(&bus)` hears every notice, and every mouse-assist note, which it hands to the sounds and the overlay. Equal notices show once, texts are made in the keyboard's language when the banner takes them and again by `shown_notices`, and only a failed module's notice offers Try again.
- **Requests:** Try again sends `Request::Retry(module)`. Quit, from the user (`Ui.quit`) or a second copy (`command(Command::Quit)`), sends `Request::Quit` once and then ends the queue, so the app's drain loop stops after it. The app calls `Kernel::retry`, or stops the modules and then `end_ui`. When the drain thread is gone, Quit ends the UI itself. Every request is sent under the hub's lock, so none lands after Quit.
- **A second copy's Show** wakes the UI through `command(Command::Show)`.
- **Tray:** `tray_show` shows or changes the icon with the keyboard window's title, in the system's language, as its tooltip; its clicks come back as `Wake::Tray`. `tray_hide` removes it; the root calls it before the UI ends.
- **Spots:** `pop_at` puts a pop-up the theme's gap above the keyboard (else below, else at the top), and `menu_at` puts the tray menu above its click; both stay inside the work area, at the scale of their screen.

## Threads

Every bridge call runs on the Qt GUI thread, including the guard and the window shape. The system look watch, the single-instance commands, the tray icon and the bus may call the hub from other threads: the hub then calls the waker the `Ui` object set, which queues the change to the Qt thread and never blocks. Show and End wakes that come before the `Ui` object exists wait in the hub; a second `Ui` object takes the wakes and warns. When the windows close or come back, `drop_waker` lets the waker go, so the next `Ui` object takes the waiting wakes quietly, and an End already sent goes to it again. The hub never holds its lock during a face, port or waker call.

## QML objects

- `Ui`: settings, language (with the size buttons' letters and names, and the tray's language) and look JSON, the keyboard's texts and the tray's (`trayText`), the space bar's text, the banner's count and a pager's number, notices (take, tell again, Try again, OK), the theme button, the light or dark switch, the backdrop, the tray icon (`trayPx`, `trayShow`, `trayHide`), where pop-ups go (`popAt`, `menuAt`), the keyboard's mode (`keepMode`, `modeJson`), the pointer overlay's state (`assistJson`), the scroll state and outline (`scrollJson`), the scroll pad's guard calls (`watchEntries` while the scroll module runs, until it holds, and `unwatchEntries` when it stops, for the keyboard window, `layUnder` once for each new set of outline edges, by their shared title, and again when the keyboard shows again, and `markPages` for the open list as it opens and at each guard run until it holds), the compiled-in assets and Quit, with signals for each change (`textsChanged` for a new keyboard language, `fontsChanged` once the hub loaded another theme's fonts, `assistChanged` for the overlay, `scrollChanged` for the scroll state, `keysChanged` when the keyboard's state changed from the bus), for the app's Show and Quit, and for tray clicks (`trayClicked`, `trayAway`).
- `Keyboard`: the board and state JSON, every click and size step, a held key's `press`, `tick`, `letGo` and `leave`, the scroll pad's arrows and Stop (`pad`, with `up`, `down`, `left`, `right` or empty for Stop) and the pointer on it (`padHover`), the language list, the window's place, the pointer, the bubble's spot, the window shape, the no-focus guard, a press frame drawn at once (`drawNow`) and the frame log's marks around a key's action (`pressStart`, `pressEnd`).

## Security

See `docs/security/kx-ui.md`. The crate root denies unsafe code; only `src/bridges/` allows it, for the cxx-qt glue and the calls into `cpp/`, with a `// SAFETY:` comment on each block (tidy F3).
