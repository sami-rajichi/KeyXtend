# kx-ui

The UI: the texts in English, French and Arabic, the `[ui]` settings, the `ui` module and the hub it shares with the app, and, with the `qt` feature (on by default), the QML module `KeyXtend.Ui` and its cxx-qt bridges (ADR-0013). It depends only on `kx-module-api`, `kx-platform` and `kx-theme`, plus Qt and Fluent.

## Build

The `qt` feature needs Qt 6.11.2: set `QMAKE` to its `qmake.exe` and put its `bin` first in `PATH` for the command. `build.rs` lists every QML file in one table (`QML`, the root first) and every bridge in `BRIDGES`, and hands the root's resource URL to the crate as `MAIN_QML`. Without the feature (`--no-default-features`) the texts, settings, hub and module still build and test, as the Linux checks need.

`cpp/` holds the C++ the bridges call where cxx-qt-lib has no binding; they include it as `kx-ui/cpp/…` through cxx-qt-build's crate include root, and `build.rs` rebuilds when it changes.

`build.rs` also adds Qt's versioned `QtGui` header folder (from `qmake -query`), for `rhi/qrhi.h`, and writes `kx-ui-build.h` under `OUT_DIR`, which defines `KX_UI_PROBES` only with debug assertions, for the test-only probes and triggers.

With debug assertions and `KX_UI_CHURN` set, the keyboard window churns through its own buttons' calls (`Churn.qml`, plan in `src/churn.rs`): theme rounds that each show every theme once, Caps Lock changes shown with no key sent (`FaceAction::FlipCaps`), then size steps up and down; the log then says `the churn ended`, for a memory check. It saves the theme and the size it steps through, and near the largest size the size ends smaller than it started. Only debug builds hold `Churn.qml`.

It also compiles in, as Qt resources, the icons the theme tokens name and every font under `assets/fonts/` (ADR-0016), found through `kx_theme::assets`; a missing icon file stops the build. `ASSETS` hands QML the fonts' URLs and the icons' URL as JSON, and the app never reads them from disk. `serve_icons` registers the icon provider (`cpp/tint.h`) on each engine before it loads QML: it draws `image://kxicon/<rrggbb>/<name>.svg` from the compiled-in icons at the size Qt asks, its ink in that tint, and refuses any other name with one warning and a clear image. Each icon is a texture of its own, outside Qt's shared atlas, so an icon between whole pixels draws the same in every run, and `Icon` keeps no cache, so each step of a colour change goes when the next comes. `serve_shadows` puts the soft shadows' adopter (`cpp/shadows.h`) on each engine before it loads QML too: `Soft.qml`, the only `RectangularShadow`, hands it its default material, which Qt 6.11 never frees, so the material goes with its shadow. Only the shown theme's files go into Qt's font list: kx-theme's `font_files.toml` names each family's files, the hub's `FontBook` (`QtFontBook` in the app) loads them before each load of the QML and, on a theme switch, before QML reads the new look, which picks its families from them, and drops the last theme's files after, so no text asks Qt for a family it lacks; `fontsChanged` follows the look's signal, so `KbWindow` picks them again (ADR-0021).

## Qt's start

The app calls `harden_qt` before Qt's app object exists. It clears with `qunsetenv` every name with a Qt prefix (`harden::QT_PREFIXES`, any case) in the C runtime's narrow copy of the environment, which Qt's byte reads use, and from the wide copy its text reads use; a name the code page narrows to a Qt one, such as a fullwidth `ＱＴ_`, goes too. It also turns off Qt Quick's shader cache on disk, and `qt_sees` and `qt_reads` tell whether Qt's narrow and wide reads still find a variable. Then the app calls `pin_adapter` with the lowest-power GPU that `kx_platform_windows::gpu` finds, which sets `ADAPTER_VAR` (`QT_D3D_ADAPTER_INDEX`), so the keyboard never wakes a big GPU. In the uiAccess build the app also passes its folder, so Qt loads plugins only from there, and calls `pin_imports` on the engine before loading: QML modules then come only from the compiled-in ones and the `qml` folder beside the app (`QML_DIR`).

Next, `pin_drawing` sets `QSG_RENDER_LOOP=basic` and `QSG_NO_DEPTH_BUFFER=1` (`harden::DRAW_VARS`), and `Shell::open` makes one shared graphics device (`Device`) when `drawing_pinned` reads both back through Qt's byte read, which each window adopts before its first frame, then loads the theme's fonts and the root QML (ADR-0021). The device is made only on the thread of Qt's app object, and elsewhere nothing is made and the pin stays; `build.rs` refuses a Qt other than the workspace's `qt_version`, as the device glue uses `rhi/qrhi.h`. When a frame finds the device lost, or drawn off the GUI thread, or a window's scene graph cannot start (`sceneGraphError`, which a `Watch` handles so Qt does not end the app), Qt's loop ends and `Shell::rebuilt` reloads the QML over the same hub. It makes the new device on the adapter the `Pick` finds anew and never drops that pin. Each try counts against `[ui] device_rebuilds`; a failed try answers `After::Wait` and a timer ends Qt's loop again after `device_retry_ms`, so the GUI thread never sleeps. Past the tries, or after an off-thread frame, each window makes its own, but a window that still cannot draw ends the app with one error. An off-thread frame, or drawing variables that did not read back, turn sharing off for the run, so no rebuild makes a shared device then. It answers `After::Again`, `Wait`, `End` or `Failed`, so the app runs the loop again or ends, with a failure when the windows could not be made again. The hub keeps whether the keyboard showed, was closed or was minimised (`Mode`), so the new `App` leaves it so. After each settings or look change, every shown window drops Qt's cached graphics once its next frame is out (`release_after_frame`), so look changes do not pile them up. Debug builds can mark the device lost (`Shell::lose`), a frame off the GUI thread (`Shell::stray`) or a window failed (`Shell::fail_window`), and count which windows draw on which device (`drawing`), which have `sceneGraphError` connected (`wired`), how many windows dropped their cached graphics (`released`) and Qt's font families (`font_families`), for the device test; release builds have none of these, so a release run of that test checks nothing.

## QML views

`qml/` holds the keyboard window and its parts, moved from the P1 test build with its look. `main.qml` makes one `Ui` and one `Keyboard` and hands them to `App`, which holds the keyboard window (`KbWindow`, its body `Plate`), the minimise bubble, the notice banner (`Notice`) and the tray menu (`TrayMenu`), each over a click-through shadow window (`Glow`), and draws the tray icon's picture (`TrayPicture`). The windows read `settingsJson`, `langJson`, `lookJson`, `boardJson` and `stateJson`, redraw from each action's `{board, state}` answer, read everything again on `settingsChanged`, and only the texts on `textsChanged`.

- **Banner:** notices queue; one shows above the keyboard (or at the bottom of the main screen while it is away) with Try again when the app can restart what failed, and OK, and says how many more wait. A new keyboard language tells the queued notices again (`shownNotices`), and a banner made again after a device loss starts from them.
- **Tray (ADR-0019):** × hides the keyboard; a click on the tray icon opens the themed menu (Show keyboard, Quit) above it, in the system's language (`trayText`, ADR-0020). It closes on a pick, a second click on the icon, a press on any of our windows (`PressWatch` hears it without taking it), and another program's window coming to the front once `[ui] tray_grace_ms` has passed since it opened. The picture is the theme's badge, drawn again when the look or the settings change, or its window's scale; a taskbar on another screen is not followed (`docs/items/P14.md`). The icon goes before the UI ends.
- **Keys:** each key's face (`KeyText`) makes only the part its kind shows, `CharLegends`, `SpaceText`, `NamedFace` or `LangFace`, and makes the new part when the kind or the language key's design changes. Each part plays its own motion: the legend rise (`Rise`) and the carousel turn. A lock glow, a light (`Led`) and its glow exist only while they show, and ease on the key (`lockLit`, `ledLit`, `ledColour`), so one made mid-fade starts where the key is. `NamedFace` makes only its icon or its label, and each shadow layer (`Shade`) only the box or the shadow it draws; `tst_budget` fails any key kind that makes more items than today.
- **Language key:** Carousel, Cycle (`LangCycle`: globe, name, one dot per layout, the current one larger) or List (name and chevron). The List opens `LangList` (with its shadow in `LangPanel`): one page of `[ui] page_rows` rows (`LangRow`) above the keyboard with its left edge at the language key, driven by the board's arrows, Enter and Esc, with a pager when there is more than one page.
- **Top bar:** the theme button cycles the themes (`bar.theme`). The lit size letter is plain text with a ring-coloured pill under it (`[bar] mark_px`).

- **Display scale (G11):** each window's size, and the keyboard's and its shadows' place, go through `Rescale`, which sets them again on a new scale or after Qt changed them, as Qt leaves the native window as it was. On a new scale, a new screen size, or when a screen comes or goes, the keyboard cuts itself again, asks to be placed again where it is in pixels, and takes the place it gets in the new Qt units (`Placing`); during a move or resize, that placement waits until it ends. A window made again after a device loss first goes where the keyboard keeps it (`st.at`), so its first report moves nothing. A new scale puts the shown bubble, banner and list back in place, the bubble from the keyboard's new place, and closes the tray menu.
- **Shadows:** a `Glow` window sits in whole Qt units around its box, so the shadow's edges meet its window's. The keyboard's shadow draws nothing while a live resize runs: each window draws on its own, so it would trail one or two frames behind.
- Every window is a no-focus tool window (ADR-0013); once shown, it is cut to its plate and corner, then guarded until the guard is done. A banner or tray menu names itself to the guard run (`Guard.qml`, which reads its title at each `Keyboard.guard(top)` try), so it lands in front where it shows again, even after a language switch.
- The keyboard and the bubble each own their tip (`Tip`), so Windows keeps it above them when the guard lifts them. A shown tip also lifts itself alone in front of our windows (`Keyboard.liftAlone`, by its title `window.tip`), hides as a guard run starts, and stays on the screen under its button.
- Names, labels and tips are translation keys, looked up in the keyboard's language: the layout's in front, unless `[ui] language` pins one (ADR-0020). Arabic flips text only; nothing mirrors, and a tip closes when the texts or the look change, so it never shows the last language.
- Keys that come in a later version are dimmed, never press, and tell readers and the tooltip "Coming in a later version".
- Text uses `Label` (grayscale, no ClearType fringes, plain text only; the texts test fails on any text element that could read markup), and hover uses `Hover` (the theme's tint, and a `Highlight` outline in high contrast). `Icon` is one `Image` the icon provider draws in its tint, with the tint's alpha as its opacity, so no icon needs an effect.

## Qt Quick tests

`qmltest/` checks the views over stand-ins for `Ui` and `Keyboard` (`FakeUi`, `FakeKeyboard`), because `qmltestrunner` cannot load a module linked into a Rust binary; `tst_app` builds `App` over them as `main.qml` does. They answer from `qmltest/fixtures/` (written by the texts test from the hub and the face's golden files) and from kx-theme's look fixtures, so QML never reads a stale value. The same test lays out the bundled fonts and icons in `target/tmp/qmltest-assets` as the app holds them, with the icon plugin (`tools/kx-test-icons`) that `qmltest/qmldir` loads, so every test's engine draws icons through the app's provider; run `cargo test -p kx-ui --test texts` first. Then run them with Qt's `bin` in `PATH` and `QML_DISABLE_DISK_CACHE=1`: `qmltestrunner -input crates/kx-ui/qmltest`. Any warning fails a test. Tests that hover pass their windows to `pointer.js`, so the real pointer goes through them and a hand on the mouse cannot move a hover. The scale and place tests share their keyboard window helpers in `kbwin.js`. `board.js` holds the one item search, which `kbwin.js` uses too, and the keys' fonts, texts and bundled font loading that `tst_corners`, `tst_order`, `tst_pictures` and `tst_lang` share. A test that needs a font Windows ships asks `fonts.js`, which skips it by name on a system without that font, such as a CI image; a missing bundled font still fails. Texts carry no bidi marks (ADR-0022), so `tst_order` checks their reading order: a twin of the drawn text with one part as a link shows, through `linkAt`, where Qt lays that part out.

To see the board before an install, set `KX_PICTURES` to a folder (relative to the repo root, such as `target/pictures`) when you run the texts test; `tst_pictures` then saves each theme's board, light and dark, and Native's high contrast, as PNGs there: English, French and Arabic plain, Arabic with Shift and with AltGr, English with Caps Lock lit and with a key pressed, the dim keys in each. Set `KX_PICTURES_BASE` to a folder of such pictures instead, and the test fails naming each picture that differs and by how many pixels. Make and compare a baseline on the same PC and display scale, as the pictures hold device pixels. With neither set, it skips.

## The `[ui]` settings

`defaults.toml` holds the values and `settings.rs` the limits of each number. `language = "auto"` follows the keyboard's language, and `en`, `fr` or `ar` pins it; the tray always follows Windows. The check refuses an unknown theme, a language that is neither `auto` nor in `LANGS`, a `min_contrast` outside `kx_theme::contrast::MIN_CONTRAST` (never below WCAG AA), and a timing or row count outside its range. `tray_grace_ms` may be 0, which turns the tray menu's grace off. `send_tries` and `send_wait_ms` set how a second copy hands Show or Quit to the running one; it reads the user's `[ui]` section without changing the file, and falls back to the defaults on any fault. `device_rebuilds` (0 to 10) caps how often one run tries to bring the windows back on a new graphics device after the device is lost or a window cannot draw; 0 goes straight to each window's own device. `device_retry_ms` (0 to 5000) is the wait before trying again when a new device could not be made yet, as a driver resets; Qt's loop runs meanwhile.

## The hub

The app makes one `Hub` over its UI ports before any window exists, so it can note the user's focus, and gets a `Receiver<Request>` with it.

- **Bridges:** `install(hub)` hands it to the QML objects once, before QML loads, since QML makes them without arguments (ADR-0018). An object made before it warns and does nothing.
- **The `ui` module:** `UiModule` needs the keyboard face; its start hands the hub the checked settings, the face and its settings handle, and its stop lets the face go.
- **Texts (ADR-0020):** two sets. The keyboard's follow the layout the face shows (`KeyboardFace::lang`): after an action whose state changed, a new language switches them and sends `Wake::Texts`. A layout language without texts gets English, and so does the time before a layout names one. The system's texts (`tray_i18n`) speak `SystemLook::ui_language`.
- **Notices:** `listen(&bus)` hears every notice. Equal notices show once, texts are made in the keyboard's language when the banner takes them and again by `shown_notices`, and only a failed module's notice offers Try again.
- **Requests:** Try again sends `Request::Retry(module)`. Quit, from the user (`Ui.quit`) or a second copy (`command(Command::Quit)`), sends `Request::Quit` once and then ends the queue, so the app's drain loop stops after it. The app calls `Kernel::retry`, or stops the modules and then `end_ui`. When the drain thread is gone, Quit ends the UI itself. Every request is sent under the hub's lock, so none lands after Quit.
- **A second copy's Show** wakes the UI through `command(Command::Show)`.
- **Tray:** `tray_show` shows or changes the icon with the keyboard window's title, in the system's language, as its tooltip; its clicks come back as `Wake::Tray`. `tray_hide` removes it; the root calls it before the UI ends.
- **Spots:** `pop_at` puts a pop-up the theme's gap above the keyboard (else below, else at the top), and `menu_at` puts the tray menu above its click; both stay inside the work area, at the scale of their screen.

## Threads

Every bridge call runs on the Qt GUI thread, including the guard and the window shape. The system look watch, the single-instance commands, the tray icon and the bus may call the hub from other threads: the hub then calls the waker the `Ui` object set, which queues the change to the Qt thread and never blocks. Show and End wakes that come before the `Ui` object exists wait in the hub; a second `Ui` object takes the wakes and warns. When the windows close or come back, `drop_waker` lets the waker go, so the next `Ui` object takes the waiting wakes quietly, and an End already sent goes to it again. The hub never holds its lock during a face, port or waker call.

## QML objects

- `Ui`: settings, language (with the size buttons' letters and names, and the tray's language) and look JSON, the keyboard's texts and the tray's (`trayText`), the space bar's text, the banner's count and a pager's number, notices (take, tell again, Try again, OK), the theme button, the light or dark switch, the backdrop, the tray icon (`trayPx`, `trayShow`, `trayHide`), where pop-ups go (`popAt`, `menuAt`), the keyboard's mode (`keepMode`, `modeJson`), the compiled-in assets and Quit, with signals for each change (`textsChanged` for a new keyboard language, `fontsChanged` once the hub loaded another theme's fonts), for the app's Show and Quit, and for tray clicks (`trayClicked`, `trayAway`).
- `Keyboard`: the board and state JSON, every click and size step, the language list, the window's place, the pointer, the bubble's spot, the window shape and the no-focus guard.

## Public API

`Hub`, `HubError`, `UiPorts`, `Request`, `Wake`, `Waker`, `Mode`, `Redraw`, `Resize`, `Shown`, `FontBook`, `UiSettings`, `Backdrop`, `SPEC`, `UiModule`, `ID`, `MANIFEST`, `Area`, `device` (`share`, `Remake`, `Rebuilds`, `Cause`, `Next`), the i18n API (`I18n`, `Lang`, `LANGS`, `AUTO`, `find`, `pick`, `os_lang`, and the `i18n::keys` module of translation keys), `harden` (`QT_PREFIXES`, `NAME_END`, `is_qt`, `qt_names`), and with `qt` also `install`, `MAIN_QML`, `QML_URI`, `ASSETS`, `serve_icons`, `serve_shadows`, `harden_qt`, `qt_sees`, `qt_reads`, `pin_adapter`, `pin_drawing`, `drawing_pinned`, `ADAPTER_VAR`, `pin_imports`, `QML_DIR`, `Shell`, `Pick`, `After` and `Device`; debug builds add `drawing`, `wired`, `released`, `font_families`, `icon_pixels` and `icon_mask` for tests.

## Security

See `docs/security/kx-ui.md`. The crate root denies unsafe code; only `src/bridges/` allows it, for the cxx-qt glue and the calls into `cpp/`, with a `// SAFETY:` comment on each block (tidy F3).
